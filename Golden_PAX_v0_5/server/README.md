# server

- `domain/` — game rules, one bounded folder per system (see each folder's README)
- `campaign/` — persistence + turn orchestration: loads/saves domain accounts through `db/`, composes the per-turn tick (see `campaign/README.md`)
- `api/` — thin HTTP layer + the API contract (see `api/README.md`)
- `db/` — SQLite schema + store
- `contentLoader.mjs` — loads and merges `content/<pack>/*.json` packs (core + campaign overlays). Ported from `GMap/server/contentLoader.mjs` with identical behavior — verified by `contentLoader.parity.test.mjs`, which diffs this loader's output against the original on the same content — but restructured from ~50 hand-written per-key merge blocks into one declarative `MERGE_SPEC` table, so adding a new content key doesn't mean copy-pasting another block.
- `raceRegistry.mjs` — race composition (parent/fork trait merging + balance-budget validation), ported unchanged from `GMap/server/raceRegistry.mjs`. Cross-cutting by design (not owned by one domain) — currently only `scripts/validateRaces.mjs` and `scripts/lintBalance.mjs` call it. **Not yet wired into any domain**, matching GMap: GMap's own caller for race composition in gameplay logic is `collectRaceEffects` in `modifierStack.mjs` (also used by `hybridRegistry.mjs`/`powerPaths.mjs`/`raceStates.mjs`), none of which are ported — that's the same deferred modifier-stack system `domain/economy`'s flow engine and `domain/diplomacy`'s `opinion.mjs` are blocked on (GMap's own `opinionTick.mjs` reads race content raw too, not through `resolveRace` — so `domain/diplomacy` is not missing anything GMap itself has here). Don't wire `resolveRace` into a domain speculatively; wire it in when `collectRaceEffects`'s actual caller is ported.
- `serve.mjs` — Express bootstrap (networking/hosting pattern carried over from GMap unchanged, see CLAUDE.md rule 8)

**Known issue carried over from GMap** (not fixed here, just not hidden): `power_paths.json` is read per-pack but was never wired into the original loader's merged output (`getContent().power_paths` is always `undefined` in GMap too — `server/powerPaths.mjs` reading `c.power_paths?.paths` silently gets `{}`). This loader matches that behavior on purpose for parity. Whether to fix it is a real product decision (are power paths meant to be live?), not a silent guess — flag it before porting `domain/economy`'s power-path pieces.
