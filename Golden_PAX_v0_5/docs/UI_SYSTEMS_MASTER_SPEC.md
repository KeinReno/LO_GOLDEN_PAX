## 1. Парадигма проекта

### 1.1 Три нерушимых принципа

Все разделы UI подчиняются одной парадигме:

**Жесты (примат).** Основные действия выполняются жестами (drag, long-press, pinch/wheel), а не кликами по меню и ползунками. Жестовый язык наследуется из карты (`FleetOrderRing`, `onUnitDrop`).

**Интуитивность.** Превью до действия, конкретика вместо абстракций, единый цветовой язык, светофор состояний (зелёный/жёлтый/красный).

**Функциональность.** Каждый пиксель — либо информация, либо действие. Правило 2 шагов: от «вижу проблему» до «действие» максимум 2 действия. Связность между разделами.

### 1.2 Главный архитектурный принцип

> **Engine мало глаголов, Content много существительных.**

Код UI не знает конкретных id сущностей. Всё живёт в content packs (JSON). UI рендерит любые сущности декларативно. Добавление новой расы/здания/технологии = новый JSON, без правки кода.

### 1.3 Единый язык жестов

| Жест | Действие | Где применяется |
|---|---|---|
| **Drag** | перенос/применение/назначение | ресурсы → планета, cognitio → технология, апгрейд → технология |
| **Long-press** | радиальное меню (стиль FleetOrderRing) | ноды технологий, ресурсы, системы |
| **Клик** | выбор/открытие | везде |
| **Свайп** | листание истории/удаление | очереди, журналы, таймлайны |
| **Pinch / колесо** | зум | графики, радиальное дерево |
| **Drag окна** | перемещение + снап | все окна разделов |

## 2. Race Registry — фундамент

### 2.1 Концепция

Расы — это **реестр как единый источник правды**. Система частично автономна: она подхватывает новые расы из реестра автоматически, но создание базовой расы остаётся за GM/человеком.

**Ключевое правило:** свойства привязаны к расе, а не к государству. Лорды Праха у Белатора и у Союза Мальфей ведут себя одинаково, потому что свойства вшиты в саму расу.

### 2.2 Три слоя данных расы

#### Слой 1: Definition (определение) — в content pack

«ДНК» расы. Не меняется в течение кампании. Живёт в `races.json`.

```json
"race_lord_dust": {
  "id": "race_lord_dust",
  "name": "Лорды Праха",
  "kind": "race",
  "origin": "бывшие люди, ставшие призраками",
  "parent": "race_human",
  "traits": [
    "trait.lord_dust.solarit_affinity",
    "trait.lord_dust.blumatit_hunger",
    "trait.lord_dust.incorporeal"
  ],
  "reproduction": { "requires": "currency.brunnatit" },
  "habitability": { "rocky": 0.7, "artifact": 1.2, "toxic": 0.9 },
  "growth": { "baseRate": 0.008, "crowdPenalty": 0.3 },
  "xenorelations": { "race_human": 0.1, "race_synth": -0.2 }
}
```

#### Слой 2: State (состояние) — в кампании

Меняется по ходу игры от RP-условий. Живёт в `data/race_states.json`, не в content pack.

```json
{
  "race_lord_dust": {
    "factionId": "faction_belator",
    "modifiers": [
      {
        "id": "mod.lord_dust.blessed_by_ritm_gorn",
        "source": "rp_event",
        "turn_applied": 14,
        "effects": [
          { "effect": "yield_mult", "args": { "currency": "currency.solarit", "mult": 1.2 } }
        ],
        "expires": null
      },
      {
        "id": "mod.lord_dust.blumatit_famine",
        "source": "deficit",
        "turn_applied": 18,
        "effects": [
          { "effect": "pop_growth_mult", "args": { "mult": 0.5 } }
        ],
        "expires": 24
      }
    ]
  }
}
```

#### Слой 3: Composition (композиция)

Раса — не монолит, а набор модулей (traits). Движок собирает свойства из модулей через `ModifierStack`.

```
race_lord_dust =
    base: race_human
  + trait.lord_dust.solarit_affinity
  + trait.lord_dust.blumatit_hunger
  + trait.lord_dust.incorporeal
  + state.modifiers (динамические)
```

### 2.3 Иерархия: Раса → Субраса → Фракция

```
race_human (человеки, базовые свойства)
├── race_human_belator (белаторцы) — универсалы, зависят от соларита
├── race_human_barial (бариальцы) — финансы/банки, дешевле постройки
├── race_human_bal_sagon (балсагонцы) — свои бафы
├── race_human_turanmal (туранмальцы) — пуриты
└── race_human_federat (федераты) — свои бафы

race_lord_dust (лорды праха) — бывшие люди, призраки
    • размножаются только при бруннатите
    • +3 к добыче соларита
    • проедают блюматит (забирают для размножения)

race_horn (хорны)
├── race_horn_narburi (нарбури) — +прирост науки (только у Белатора)
└── race_horn_tornklif (торнклифа) — другой баф, не наука
```

Каждый уровень несёт traits, которые складываются.

### 2.4 Механизм клонирования (fork)

Вместо копипасты расы — `fork` с overrides:

```json
"race_karned_lithoid": {
  "id": "race_karned_lithoid",
  "base": "race_elan",
  "forked_from": "race_elan",
  "name": "Карнедские литоиды",
  "override_traits": ["trait.lithoid.crystal_metabolism"],
  "remove_traits": ["trait.elan.organic_growth"],
  "state_overrides": { "habitability": { "rocky": 1.3 } }
}
```

Клон наследует всё от `base`, переопределяет только отличия. Если изменится базовая раса — клон автоматически подхватит изменения (кроме переопределённого).

### 2.5 Автономность системы

**Добавление новой расы.** Агент добавляет запись в `races.json` + её traits. Движок на следующем тике автоматически включает её в расчёты населения, экономики, боя. Варианты зданий/юнитов становятся доступны там, где раса присутствует. Код не меняется.

**Клонирование под государство.** `fork` с overrides (см. 2.4).

**Модификация через RP.** Модификатор пишется в `race_states.json`. Движок учитывает его при расчёте. Истёк срок — модификатор отваливается автоматически.

### 2.6 Правила баланс-бюджета

1. **Лимит traits:** базовая раса ≤ 6 traits, субраса ≤ 4.
2. **Правило клонирования:** клон не может добавлять больше N traits сверх базы.
3. **Баланс-бюджет:** каждый trait имеет «вес». Суммарный вес расы ≤ порога.
4. **Канон vs динамика:** Definition меняется только через GM с ревью. State может менять RP-движок автоматически.
5. **Истечение модификаторов:** каждый state-модификатор обязан иметь `expires` или `permanent: true`.

## 3. Variant System — система вариантов

### 3.1 Принцип

> **Любая сущность игры имеет generic-шаблон (base) и может иметь расовые/субрасовые/фракционные варианты (variants), которые наследуют base и переопределяют часть свойств.**

Работает для зданий, юнитов, технологий, кораблей, способов добычи ресурсов.

### 3.2 Здания: generic + варианты

**Generic-шаблон (база):**

```json
"building.solarit_extractor": {
  "id": "building.solarit_extractor",
  "kind": "variant_base",
  "name": "Экстрактор соларита",
  "category": "A",
  "tier": 2,
  "cost": { "currency.metal": 30, "currency.supply": 5 },
  "effects": [
    { "effect": "yield_flat", "args": { "currency": "currency.solarit", "amount": 2 } }
  ],
  "variants": [
    "building.solarit_extractor.belial",
    "building.solarit_extractor.lord_dust"
  ]
}
```

**Вариант бариальцев** (дешевле, +1 к добыче):

```json
"building.solarit_extractor.belial": {
  "id": "building.solarit_extractor.belial",
  "base": "building.solarit_extractor",
  "name": "Экстрактор соларита (бариальский)",
  "tags": ["race_human_belial"],
  "cost": { "currency.metal": 24, "currency.supply": 4 },
  "cost_mult": 0.85,
  "extra_effects": [
    { "effect": "yield_flat", "args": { "currency": "currency.solarit", "amount": 1 } }
  ],
  "flavor": "Бариальцы удешевляют строительство за счёт коммерческих контрактов"
}
```

**Вариант лордов праха** (дороже, +3, но проедают блюматит):

```json
"building.solarit_extractor.lord_dust": {
  "id": "building.solarit_extractor.lord_dust",
  "base": "building.solarit_extractor",
  "name": "Экстрактор соларита (лордов праха)",
  "tags": ["race_lord_dust"],
  "cost": { "currency.metal": 42, "currency.supply": 8 },
  "extra_effects": [
    { "effect": "yield_flat", "args": { "currency": "currency.solarit", "amount": 3 } }
  ],
  "upkeep_effects": [
    { "effect": "consume", "args": { "currency": "currency.blumatit", "amount": 1, "reason": "размножение_лордов_праха" } }
  ],
  "requires": [
    { "resource": "currency.brunnatit", "min_amount": 1, "reason": "лорды праха размножаются только при бруннатите" }
  ],
  "flavor": "Призрачные лорды извлекают соларит из самой ткани реальности"
}
```

**Обратный эффект (блюматит):** одна и та же раса даёт бонус в одном контексте и штраф в другом.

```json
"building.blumatit_extractor.lord_dust": {
  "id": "building.blumatit_extractor.lord_dust",
  "base": "building.blumatit_extractor",
  "name": "Экстрактор блюматита (лордов праха)",
  "tags": ["race_lord_dust"],
  "extra_effects": [
    { "effect": "yield_flat", "args": { "currency": "currency.blumatit", "amount": 0 } }
  ],
  "self_consume": {
    "currency": "currency.blumatit",
    "percent": 0.5,
    "reason": "лорды праха забирают половину блюматита для размножения"
  },
  "flavor": "Лорды праха добывают блюматит, но половину съедают сами"
}
```

### 3.3 Юниты: generic + варианты

```json
"unit.legion_infantry": {
  "id": "unit.legion_infantry",
  "kind": "variant_base",
  "name": "Пехотный легион",
  "cost": { "currency.supply": 20 },
  "stats": { "damage": 10, "defense": 12, "hp": 100 }
}

"unit.legion_infantry.lord_dust": {
  "id": "unit.legion_infantry.lord_dust",
  "base": "unit.legion_infantry",
  "name": "Призрачный легион (лорды праха)",
  "tags": ["race_lord_dust"],
  "extra_stats": { "defense": 8, "hp": -20, "stealth": 15 },
  "traits": ["psionic", "incorporeal"]
}
```

### 3.4 Логика выбора варианта движком

```
1. Игрок хочет построить "Экстрактор соларита"
2. Движок смотрит состав населения на планете/в системе
3. Находит расы: белаторцы (60%), лорды праха (25%), бариальцы (15%)
4. Собирает доступные варианты:
   - generic (всегда доступен)
   - lord_dust (раса лордов праха ≥ порога, например 20%)
   - belial (бариальцев 15% < 20%, недоступен)
5. Игрок выбирает вариант из доступных
6. Движок применяет cost + effects + upkeep_effects этого варианта
```

**Порог доступности** настраивается в `rules.json` (мин. доля расы в системе).

## 4. Раздел «Экономика»

### 4.1 Контекст

Раздел **«Экономика»** — внутренний командный пульт хозяйства фракции. Отделён от раздела **«Рынок»** (внешняя торговля).

| Раздел | Назначение | Аудитория |
|---|---|---|
| 🏛 **Экономика** | Внутреннее управление: производство, бюджет, склад, налоги | одна фракция |
| 💱 **Рынок** | Внешняя торговля: ордера, котировки, сверхдержавы | межфракционный |

**Технологии в этот раздел НЕ входят** — они в разделе «Наука».

### 4.2 Структура окна: Sidebar + контент

Перетаскиваемое, изменяемое по размеру окно (как в десктопных стратегиях).

```
┌─────────────────────────────────────────────────────────┐
│ 🏛 ЭКОНОМИКА · Империя Белатор              [_][✕]      │ ← drag-зона
├──────────────┬──────────────────────────────────────────┤
│  SIDEBAR     │           КОНТЕНТ                        │
│  📊 Обзор    │  (выбранный раздел)                      │
│  🏭 Произв   │                                          │
│  💰 Бюджет   │                                          │
│  📦 Склад    │                                          │
│  📜 Политики │                                          │
└──────────────┴──────────────────────────────────────────┘
```

### 4.3 Раздел «Обзор»

Отвечает на вопрос: **«Я зарабатываю или прогораю?»**

- Три метрики: Казна / Доход/ход / Расход/ход (NumberTicker)
- Сетка 6 категорий A–F (BentoGrid) со спарклайнами
- Графики: линия казны с прогнозом, пончик расходов, бары A–F
- Блок предупреждений (дефицит, высокое давление)

### 4.4 Раздел «Производство»

Управление добычей и RPS-трансформацией по планетам.

- Визуализация RPS-цикла: `A → B → C → D → E → F → A`
- Список систем с производством
- Клик по системе → окно «Система» рядом (снап)
- Drag категории на категорию → трансформация (жест вместо ползунка)

### 4.5 Раздел «Бюджет»

Прозрачность доходов и расходов. Ответ: **«Куда утекает?»**

- Сводка: Доходы / Расходы / Баланс
- Timeline транзакций (группировка по ходам)
- Пончик расходов по статьям
- Разбивка модификаторов (`explain.lines`)

### 4.6 Раздел «Склад»

Запасы фракции и резервы. Ответ: **«Что у меня лежит?»**

- Карточки запасов со спарклайнами
- Резервы под стройку
- Drag ресурса на планету/карту → «Продать / Зарезервировать / Караван»

### 4.7 Раздел «Политики»

Налоги, законы, экономические доктрины.

- Налоги: карточки ставок по слотам, живое превью эффекта
- Законы: активные/доступные
- Доктрины: «Военная экономика», «Торговая экспансия», «Мирный рост»

### 4.8 Графики и диаграммы

Каждый график отвечает на один вопрос игрока.

| Вопрос | Тип | Данные |
|---|---|---|
| «Я зарабатываю?» | Линия казны + прогноз | `recent` (ledger) |
| «Куда утекает?» | Пончик расходов | `recent` по `reason` |
| «Чего не хватает?» | Бары A–F (произв/потребл) | `flows`, `explain` |
| «Как менялось?» | Спарклайн | история stocks |
| «Что по ценам?» | Линия котировок | **Рынок** (не тут) |

**Прогноз казны** — киллер-фича: пунктир показывает тренд на 3–5 ходов.

**Библиотека:** recharts (линия, бары, пончик) + спарклайны на чистом SVG. **Sankey — НЕ в v1.**

### 4.9 Связность окон (master–detail)

Окно Экономики — навигатор к окнам Систем, Рынка, Науки.

- **Экономика → Система:** клик по планете в «Производстве» → окно «Система» рядом (снап), хлебные крошки, подсветка связи.
- **Склад → Рынок:** drag ресурса «Продать» → Рынок с предзаполненным ордером.
- **Политики → Бюджет:** изменение налога показывает эффект в бюджете.
- **Обзор → Наука:** предупреждение «нужна технология» → ссылка на Науку.

## 5. Раздел «Наука»

### 5.1 Текущее состояние

Уже реализовано и работает хорошо:

- `ResearchPanel.tsx` — основной контейнер (запас cognitio, табы ветвей, nextBuy, карточка технологии, проверка locks)
- `ResearchRadialTree.tsx` — радиальное дерево (6 осей A–F, кольца эпох, pan/zoom, звёзды апгрейдов); **основной вид дерева на десктопе/планшете** (`ResearchPanel` переключает на overview+matrix только на мобильном)
- `technologies.json` — 2397 строк, 6 категорий, 4-5 эпох, апгрейды, прорывные, расовые эксклюзивы
- `techActions.mjs` — серверная логика (`researchTech`, `researchUpgrade`, `canBuildWithTech`)

### 5.2 Эффекты технологий

| Эффект | Описание |
|---|---|
| `unlock_tech_tier` | Открывает доступ к зданиям тира |
| `unlock_property` | Разблокирует свойство (shield, psion_store) |
| `production_mult` | Множитель производства (×1.1 = +10%) |
| `upkeep_mult` | Множитель апкипа (×0.9 = -10%) |
| `production_flat` | Плоский бонус (+N/ход) |
| `research_cost_mult` | Скидка на исследования (×0.92 = -8%) |
| `unit_upgrade` | Апгрейд юнитов (corvette → frigate) |
| `stat_mult` | Множитель статов |
| `capacity_add` | Добавляет ёмкость |

### 5.3 Очередь исследований

**Три режима исследования:**

| Режим | Действие | Стоимость |
|---|---|---|
| **Мгновенное** | Изучить сейчас | Полная стоимость cognitio |
| **В очередь** | Авто-исследование | 0 AP, списывается по мере накопления |
| **Ускоренное** | Профинансировать в очереди | +50% к стоимости, 1 ход |

**UI очереди:**

```
┌─────────────────────────────────────────────────────────┐
│ 📋 Очередь исследований                                 │
├─────────────────────────────────────────────────────────┤
│  1. ⚡ Глубинный анализ планет (B2)                     │
│     💰 24 cognitio · ⏱ 8 ходов                         │
│     [⚡ Ускорить: 36 cognitio → 1 ход] [✕ Убрать]       │
│  2. Кристалл-синхрон (B2)                               │
│     💰 28 cognitio · ⏱ 10 ходов                        │
│     [⚡ Ускорить] [↑] [↓] [✕ Убрать]                    │
│  Итого: 94 cognitio · ~32 хода                          │
└─────────────────────────────────────────────────────────┘
```

**Жесты для очереди:** drag вверх/вниз (приоритет), swipe влево (удаление), drag cognitio на технологию (ускорение).

### 5.4 Трёхуровневая проверка доступности

```typescript
type TechAvailability = {
  available: boolean;   // можно изучить сейчас
  reason: string | null;
  canQueue: boolean;    // можно добавить в очередь
};
```

Статусы визуализируются цветом: зелёный (доступно), жёлтый (можно в очередь), красный (заблокировано).

**Баг-фикс:** нельзя добавить в очередь технологию без выполненных пререквизитов или без нужной черты фракции.

### 5.5 Связность с другими разделами

- **Наука → Экономика:** клик по эффекту `production_mult` → Производство с фильтром.
- **Наука → Силы:** клик по эффекту `unit_upgrade` → Силы с подсветкой улучшенных юнитов.
- **Силы → Бой:** readiness / «В БОЮ» → engagement или card battle table (`FORCES_SECTION_SPEC.md`).
- **Силы → Экономика:** upkeep strip → Экономика.
- **Экономика → Наука:** предупреждение «нужна технология X» → ссылка на Науку.

### 5.6 Планировщик и история

- **Планировщик:** дерево путей «чтобы изучить X, нужно сначала Y → Z», расчёт стоимости и времени.
- **История исследований:** Timeline (ход 5: geology, ход 8: deep_prospecting).
- **Сравнение альтернатив:** таблица эффектов двух технологий одной эпохи.
- **Симулятор «Что если»:** прогноз потоков через 5/10/20 ходов.

## 6. Расово-фракционная система технологий

### 6.1 Три слоя доступности

#### Слой 1: Базовый пул (кто МОЖЕТ изучить)

Определяется расовым составом и чертами фракции.

```json
{
  "id": "faction_belator",
  "baseTechPool": {
    "races": ["race_human", "race_elan", "race_horn", "race_swarm"],
    "traits": ["trait.imperial", "trait.multi_species"]
  }
}
```

#### Слой 2: Приобретённый пул (кто УЖЕ ИМЕЕТ)

Технологии через обмен, покупку, исторические события.

```json
{
  "factions": {
    "faction_karned": {
      "acquiredTechs": [
        {
          "techId": "tech.human.agriculture",
          "source": "historical",
          "acquiredTurn": 0,
          "note": "Наследие человеческих колонистов"
        },
        {
          "techId": "tech.federation.shields",
          "source": "trade",
          "acquiredTurn": 15,
          "tradedWith": "faction_federation"
        }
      ]
    }
  }
}
```

#### Слой 3: Рынок технологий (кто может КУПИТЬ)

NPC-базар или межфракционная торговля.

```json
{
  "tech.khanate.market": {
    "listings": [
      {
        "techId": "tech.elan.lithoid_conversion",
        "price": { "currency.metal": 200, "currency.cognitio": 50 },
        "minRelation": "trade"
      }
    ]
  }
}
```

### 6.2 Наследственные технологии

При преобразовании расы (литоидизация) технологии НЕ удаляются, но помечаются как `source: "historical"` и не могут быть переданы.

**Сценарий Карнедов:** люди в составе → преобразованы в литоидов → человеческие технологии остаются как «наследие», но не передаются.

### 6.3 Обмен технологиями

```json
{
  "intent.trade_tech": {
    "ap": 2,
    "ops": ["transfer_tech"],
    "params": ["techId", "targetFactionId", "price"],
    "requires": { "diplomacy": ["trade", "alliance"] }
  }
}
```

### 6.4 Примеры фракций

**Империя Белатор** (люди + эланы + хорны + Рой):

```json
{
  "id": "faction_belator",
  "availableRaces": ["race_human", "race_elan", "race_horn", "race_swarm"],
  "traits": ["trait.imperial", "trait.multi_species"]
}
```

**Монархия Карнед** (эланы → литоиды → механисты):

```json
{
  "id": "faction_karned",
  "availableRaces": ["race_elan", "race_lithoid", "race_synth"],
  "traits": ["trait.mechanization"]
}
```

**Гничи** (коллекционеры):

```json
{
  "id": "faction_gnichi",
  "availableRaces": ["race_human", "race_psionic", "race_synth", "race_swarm", "race_elan", "race_horn"],
  "traits": ["trait.tech_collector"]
}
```

**Туранмал** (только люди):

```json
{
  "id": "faction_turanmal",
  "availableRaces": ["race_human"],
  "traits": ["trait.purist"]
}
```

**КорвунТай** (уникальные):

```json
{
  "id": "faction_korvuntai",
  "availableRaces": ["race_human", "race_unknown"],
  "traits": ["trait.alien_tech"]
}
```

### 6.5 Логика доступности

Технология доступна фракции, если:

```
1. Теги технологии ∩ availableRaces фракции ≠ ∅
   ИЛИ технология без тегов ИЛИ tags содержит "general"
2. raceLock выполнен (≥30% населения расы) ИЛИ отсутствует
3. factionTraitLock выполнен ИЛИ отсутствует
4. Все prerequisites изучены
```

## 7. Aceternity UI и дизайн-система

### 7.1 Принцип

Aceternity — библиотека маркетинговых компонентов. Для игры брать **выборочно** и перекрашивать под имперскую палитру.

### 7.2 Брать

| Компонент | Куда | Зачем |
|---|---|---|
| `AnimatedTooltip` | все ресурсы/цифры | интуитивность |
| `NumberTicker` | казна, доход, запасы | живые цифры |
| `HoverBorderGradient` | кнопки, активные строки | обратная связь |
| `CardSpotlight` / `Spotlight` | карточки категорий, планет | подсветка |
| `GlowingEffect` | важные кнопки, дефициты | акцент |
| `BentoGrid` | сетка категорий в Обзоре | дашборд |
| `AnimatedModal` | подтверждение политик | контекст |
| `Timeline` | журнал транзакций, история науки | история |
| `DirectionalAwareHover` | карточки планет | отклик на жест |
| `Lens` | лупа на графике | детали |
| `Pin` | закрепление окон | функциональность |
| `Tabs` | вкладки окон | стандарт |

### 7.3 НЕ брать

| Компонент | Почему |
|---|---|
| `BackgroundBeams`, `SparklesCore`, `Meteors`, `FlickeringGrid` | фоновые эффекты на весь экран, едят FPS |
| `HeroHighlight`, `MacbookScroll`, `Lamp`, `TextPressure` | лендинговые |
| `InfiniteMovingCards`, `CardStack` | карусели-шоу |
| `WobbleCard`, `Confetti` | ломают серьёзный тон |

### 7.4 Цвета категорий (из economy_schema.json)

| Категория | Цвет | Hex |
|---|---|---|
| A Сырьё | бронза | `#8d6e3a` |
| B Материалы | сталь | `#7a8fa6` |
| C Промышленность | янтарь | `#c98a3a` |
| D Энергия | золото | `#e8c44c` |
| E Биомасса | зелень | `#5cdb95` |
| F Знание | фиолет | `#9b6bff` |

### 7.5 Семантические цвета

- ✅ Зелёный: избыток, доход.
- ❌ Красный: дефицит, расход.
- ⚠ Жёлтый: узкое место, предупреждение.
- 🔵 Голубой/циан: нейтральная информация, акцент Империи.

### 7.6 Фон окна

- `bg-slate-950/90` + `backdrop-blur-md`.
- Рамка: тонкая неоновая (`border-cyan-500/30`).
- Не больше 1–2 «тяжёлых» glow-эффектов на окно.

### 8.1 Главный принцип

### 8.2 Запрещено (антипаттерны)

- Дублировать данные.
- Создавать циклические зависимости.

- Добавлять новые записи в JSON (races, buildings, technologies).
- Добавлять новые traits в реестр.

## 10. Глоссарий

| Термин | Значение |
|---|---|
| **Race Registry** | Реестр рас как единый источник правды |
| **Definition** | Определение сущности в content pack (не меняется в кампании) |
| **State** | Состояние сущности в кампании (меняется от RP) |
| **Composition** | Сборка свойств из модулей (traits) |
| **Variant** | Расовая/фракционная вариация сущности |
| **Fork** | Клонирование сущности с overrides |
| **ModifierStack** | Единый движок свёртки бафов/дебафов |
| **Trait** | Модуль свойства расы (баф/дебаф) |
| **RPS-цикл** | Цикл трансформации ресурсов A→B→C→D→E→F→A |
| **Cognitio** | Валюта науки (категория F, Знание) |
| **Breakthrough** | Прорывная технология (Era 5, end-game) |
| **Наследственная технология** | Получена через историю, не передаётся |
