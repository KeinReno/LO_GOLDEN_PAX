## 1. Контекст и цель

Отправная точка разбора: текущая модель экономики (**A–F категории × T1–T10 тиры**, см. `content/core/economy_schema.json`) технически работает (`server/economyTick.mjs`, `server/flowEngine.mjs` — реальный, не заглушка), но **непонятна игроку** и **нивелирует ценность конкретных ресурсов**. Богатая титаном/рэдитом планета не ощущается уникальной, потому что оба ресурса сливаются в одну и ту же категорийную валюту.

Цель всего последующего дизайна одна: **дать игроку инструменты и свободу, а не навязанный маршрут** — песочница для отыгрыша, где решения (какой путь развития выбрать, на каком ресурсе строить экономику, с кем торговать) реально на что-то влияют и видны без необходимости лезть в таблицы.

## 2. Модель времени: Order + AP

> **Статус (B4, 2026-08-10):** ✅ пилот реализован. `server/orderEngine.mjs`, `world.orders`, `resolveDueOrders()` в `processTurn.mjs` (после economy tick). AP = параллельные слоты активных ETA-Order (тратится при создании, освобождается при `resolved`/`cancelled`). UI: чипы процессов в `OrderTray.tsx`.

Ход остаётся сутки (публикация/снапшот, `turnHistory`), но **не единственная единица времени внутри себя**.

**Order** — единая структура для процессных действий (полёт, стройка, исследование, осада):

```text
Order {
  type: "fleet_move" | "build" | "research" | "siege" | ...
  startedAt, baseDuration, modifiers[], resolvesAt   // fixed-ETA
  progress, ratePerTurn                              // accumulating (исследования)
}
```

- **Fixed-ETA** (перелёт, стройка): таймер стартовал → идёт неизменно, кроме явных ускорений.
- **Accumulating** (исследования, возможно культура/идеология): прогресс-бар, ETA — прогноз, не гарантия, честно пересчитывается при апгрейде инфраструктуры.

**AP (Action Points)** — не «число кликов в день», а сколько параллельных Order фракция может держать в очереди одновременно. Пополняется по ходу/по часам (см. `resolveEmpireApMax` в `server/economyTick.mjs`, уже существует как черновой механизм).

**Ускорения — явные, не мгновенные:** ресурс→скорость (×2, не телепортация), закон/эдикт (постоянный множитель), инфраструктура (верфь/лаборатория выше уровнем). Никогда «заплати и получи сейчас».

**UI-формат везде одинаковый** (echo для ресурсов/времени/боя):

```text
База → модификаторы → итог
72ч → верфь ×0.7 → закон ×0.9 → 46ч (осталось 29ч)
```

## 3. Три категории действий

> **Статус (B4, 2026-08-10):** ✅ разметка `category` в `content/core/intents.json`. Pending-реакции — через существующий `diploOffers.mjs` (без дублирующего Proposal-типа). Категория B в UI — статус-бейдж, не прогресс-бар.

| Категория | Признак | Примеры | Структура данных |
|---|---|---|---|
| **A. Мгновенные** | применяется сразу, эффект виден в момент | смена стойки флота, объявление войны, смена налога, принятие закона | прямая мутация состояния |
| **B. Ожидающие реакции** | ждём решение другого агента, не время | предложение союза/сделки | `Proposal { status: pending\|accepted\|rejected }`, **без ETA вообще** |
| **C. Ожидающие время** | физический процесс | перелёт, стройка, исследование, осада, разведка | `Order` (см. §2) |

**Важно:** нельзя показывать прогресс-бар для категории B (ожидание игрока) — это создаёт ложное ощущение предсказуемости. Только статус-бейдж («Ожидает ответа Таала»).

Бой — гибрид: инициируется автоматически (по факту прибытия Order), резолвится мгновенно по формуле (категория A), опционально накопительная осада — категория C.

## 4. Валюта и Биржа

### Что уже реально работает
- `content/core/faction_currency_bindings.json` — привязка валюты фракции к конкретному анкор-ресурсу (`fxCurrencyId` + `treasuryPeg`) уже существует как данные.
- `server/economyTick.mjs:786-810` — казна фракции зеркалит `treasuryPeg` при тике.

### Найденный баг
Зеркалится **весь net категории Materia (B)**, а не добыча конкретно анкор-ресурса. Т.е. потеря шахты соларита не бьёт по «соларитовой» казне, пока жив любой другой B-ресурс. **Фикс:** после перехода на именные стоки (§5) казна должна зеркалить именно добычу `treasuryPeg`-ресурса.

> **Статус (B1, 2026-08-10):** ✅ решено. `treasuryPeg` канал берёт `strategicExtraction[peg]`, именной сток кредитуется через `strategic_extraction`; параллельный bridge metal/supply больше не зеркалит positive `categoryNet`.

### Чего не хватает
- Курс между `fx.*`-валютами разных фракций **физически отсутствует** в `economy_schema.json → placeholder_rates` (там только 9 пар между категорийными валютами A-F).
- Курс сейчас — статичная GM-таблица (`server/marketRates.mjs`, редактируется через `GmMarketRatesEditor.tsx`), не формула.

### Предложение (детальный дизайн — TODO, следующая сессия)
- Курс `fx.A ↔ fx.B` через общий расчётный номинал («кредит Биржи»), не N² пар.
- Формула = f(резервы анкор-ресурса, добыча/ход), с инерцией (не обнуляется одним рейдом).
- Ордербук для стратегических именных ресурсов; bulk-ресурсы — по упрощённой «продать по текущей ставке».
- Манипуляция курсом через фиктивные сделки — курс считается по макропоказателям (резервы+добыча), не по объёму сделок.

## 5. Ресурсы: идентичность вместо бакетов

### Диагноз (подтверждено чтением кода)
`server/flowEngine.mjs → addPlanetExtraction()` коллапсирует конкретный ресурс в бакет `flows[category][tier]` **на первом же шаге добычи** — идентичность теряется не на складе, а сразу при добыче. Два разных ресурса одной категории/тира неотличимы уже на входе.

При этом **бой** (`server/combatResolve.mjs`) и **постройки** (`buildingInst.slotFills`) уже оперируют конкретными id ресурсов — рассинхрон между подсистемами, не архитектурная пропасть.

### Решение
- **Category (A–F) и Tier остаются метаданными** для сопоставления слотов («любой B≥1») и дашборда (6 чисел по умолчанию) — не местом хранения.
- **Сток/расход/торговля — по конкретному resourceId.** Ledger хранит `map.solari`, `map.titan` и т.д. отдельно, не `currency.materia`.
- Постройки/слоты по-прежнему пишут абстрактное требование (`{category:"B", tier:">=1"}`) для лёгкости авторинга — но при заполнении слота **списывается конкретный сток**, greedy/приоритетно (задел уже есть: `eco.flowPriorities`).
- RPS-цепочка A→B→C→D→E→F **не исчезает** — становится честной: конкретная постройка потребляет конкретный сток и производит конкретный сток (завод: стеклосталь+гео-кристалл → бронеплита), а не переливание чисел.

### Расслоение на два ранга (не все 86 ресурсов равны)
- **Bulk (~65-70)** — сырьё биомов, взаимозаменяемо внутри category+tier для построек, авто-расход по наличию.
- **Strategic/именные (~10-15)** — валютные анкоры, гейты уникальных технологий/построек/кораблей. Всегда явные, никогда «любой B».

### Ответ на «сколько титана нужно для крейсера»
Two-tier UI: **быстрая постройка** — живая котировка, посчитанная по реальному складу («Корпус: 8× Титан-VI, склад 1200 ✅ / Оружие: 4× Фокус-кристалл, склад 12 ⚠️ хватит на 3 шт») + **кастомный лоадаут** — ручная замена конкретного ресурса в слоте для тех, кто хочет оптимизировать. Панель «военный потенциал» — максимум юнитов по самому дефицитному ресурсу (расширение существующей `bottlenecks()` в `flowEngine.mjs` с категорий на именные ресурсы).

## 7. Двухуровневая ценность ресурса

Развитие идеи ролей — ресурс имеет ценность на двух независимых осях одновременно:

**Уровень 1 — Рецептурная роль (именная).** Конкретный модуль/постройка требует 1-3 **конкретных** ресурса по id («солариевый щит» = соларит + ещё 1-2 позиции явно). Штучные, авторские связки.

**Уровень 2 — Категорийный (Role Aggregate).** Накопленный **за всю игру** объём добычи по роли (не текущий склад!) — `RoleScore(роль) = Σ (добыто_за_игру × вес_тира)`. Порог открывает не рецепт, а **новую ветку возможностей**: уникальный класс корабля, закон, постройку, техноветку (см. §10 — здесь же порог для открытия **пути развития**).

Свойства:
- Не тратится (в отличие от валюты/ресурса) — это достижение, не расход.
- Никогда не отбирается при потере территории (философия «специализация = возможность, не наказание», как для валют и рас).
- Дёшево считается — сумма с весами, тот же тип расчёта, что уже в `runEconomyTick()`.

Пример открытий по ролям (не финально, требует проработки руками):

| Роль | Открывает |
|---|---|
| 🛡 Структурный | класс «Дредноут», доктрина «Тяжёлая броня», крепость-станция |
| ⚡ Энергетический | уникальный реактор/оверчардж, энергополитика |
| 🎯 Ударный | осадная платформа, доктрина «Авангард» |
| 🔰 Защитный | планетарный щит, доктрина «Бастион» |
| 🚀 Мобильность | класс рейдера, прыжковая техноветка |
| 🧠 Когнитивный | псионическая ветка, орден-исследователь |
| 🌱 Биологический | ветка эволюции расы, биокорабль |
| ✨ Экзотический | реликтовая технология, фракционное «чудо» |

## 8. Ресурсы-клоны — что с ними делать

**Решено: вариант А** — дать вторую отличительную черту вместо слияния. Железо/титан/стеклосталь/титаний (сейчас все `["strong"]`) получают по второй роли/свойству, создающей реальный выбор:

- Титан — `strong + lightweight` → бонус скорости корабля.
- Стеклосталь — `strong + optics` → бонус точности/сенсоров.
- Титаний — `strong + heat_resistant` → бонус против конкретного типа оружия.

Это превращает «богатую титаном планету» из абстрактно-полезной в конкретно-ценную («мои корабли отсюда быстрее»), плюс сохраняет биомную географию карты как источник стратегического разнообразия.

## 10. Технологии: пути развития

### Диагноз (подтверждено чтением кода)
- `content/core/technologies.json` — 428 технологий, единый плоский пул, `category` (A-F) + `era` + `cost` (cognitio) + `prerequisites` + `tags` (почти все `["general"]`).
- Только **6 из 428** имеют `raceLock` (race_psionic, race_swarm, race_synth) или `factionTraitLock` (trait.technocracy, trait.war_economy, trait.psi_doctrine) — разрозненные исключения, не система.
- `src/state/techGate.ts` — доступность построек считается через `techTiers` (максимальный открытый тир на категорию) + `unlockedProperties` — полностью категорийная, расо-нейтральная логика.
- Итог: общий пул технологий сейчас **буквально общий для всех**, вопреки философии игры («технологии человека должны отличаться от технологий эланов»).

### Предложение: Path (путь развития) как единица контента

**Таксономия путей = переиспользовать 8 ролей из §6.** Один и тот же словарь (🛡⚡🎯🔰🚀🧠🌱✨) значит одно и то же везде: роль ресурса, ось Role Aggregate, и теперь — направление технологического пути. Это даёт игроку **один** выученный язык на все три системы вместо трёх разных.

Существующие `raceLock`/`factionTraitLock`-примеры уже намекают на реальные темы: race_psionic→🧠, race_swarm→🌱, trait.war_economy→🎯/🛡, trait.psi_doctrine→🧠 — переразметка, не изобретение с нуля.

**Механика:**
1. **Core/Universal пул** остаётся — большая часть из 428 текущих технологий (базовая инфраструктура, общие производственные техи) доступна всем всегда. Путь — это специализация *поверх* базы, не замена ей. (Так же не нужно резать/пересортировывать все 428 разом — миграция постепенная.)
2. **Раса даёт стартовую аффинити к пути**, не жёсткий лок — соответствует принципу «без дебафов»: раса роя стартует с 🌱 открытым и, вероятно, дешевле исследует его технологии, но не заблокирована от остальных путей.
3. **Открытие нового пути = RoleScore-порог (§7) + «Прорыв» (Breakthrough-tech).** Достижение порога делает путь *доступным* к открытию; сам прорыв — намеренная, крупная трата cognitio в Core-пуле, а не тихий автоматический анлок. Даёт игроку явный, ощутимый момент выбора.
4. **Техи вне открытых путей — не исследуются напрямую**, но достижимы через уже существующие каналы: торговля/дипломатия (`superpower_market.json`-подобные листинги, потенциально technology-as-listing), завоевание (трофей при взятии системы с лабораторией), шпионаж (кража, новый intent поверх существующей fog/intel системы). Ничего из этого не новая подсистема — расширение того, что уже есть.
5. Не запрещено дойти до всех путей за долгую партию — специализация это стартовое ускорение и идентичность, не потолок.

### Решено
- **8 материальных путей — закрытый список, без добавок в ту же ось.** Всё, что не ложится ни в одну из 8 ролей, остаётся в Core/Universal пуле («без пути» = общий доступ).
- **Но заведено отдельное, третье семейство путей — Гражданские (не материальные, не Силы):** 🪙 Путь Торговли (кормится объёмом Биржи/договоров/трафика — сюда наконец приземляются Эладон, Бореальцы, Вольногаванийцы) и 🎭 Путь Культуры (кормится долей культуры/верой/лояльностью — наконец находит применение почти пустым `faiths.json`/`cultures.json`). Не RoleScore-производные — другая валюта входа (обмен/влияние, не добыча), поэтому не 9-я материальная роль, а отдельная ось наравне с Путями Силы. Ханство Золотой Луны — живой пример фракции, полностью построенной на этом семействе.
- **UI-правило (уточнено позже в сессии — отменяет более раннюю версию этого пункта):** прятать имеет смысл только то, что физически недостижимо для игрока. Материальные и Гражданские пути достижимы для любой фракции с первого хода — оба семейства **видны всегда**, равноценно, единой компактной полосой из 10 иконок (не 8 полных панелей + 2 скрытых). Прячется только то, что реально недоступно — Пути Силы у рас без допуска (см. §12 Происхождение, `LORE_COSMOLOGY_SPEC.md`). *Ранее обсуждалась формулировка «показывать только тем, кто накопил» — отменена; гражданские пути около нуля в начале — норма, как у материальных RoleScore.*
- **✅ Реализовано (B6, 2026-08-10):** `content/core/civic_paths.json`, `server/civicTick.mjs` → `eco.civicScores.trade|culture` (накопительно), разблокировки через `unlock_property` (постройки) и `eco.laws` (законы). - **Синты → 🧠 Когнитивный** (машинный интеллект = когниция, не энергия). Общее правило для остальных 16 рас: смотреть, какая роль уже проступает через существующую механику расы (currency peg, reproduction-resource, старый raceLock), не придумывать сверху. ## 11. Итоговая архитектура (как всё связано)

> Дополнено после лорной сессии — см. `LORE_COSMOLOGY_SPEC.md` за полной космологией. Здесь — только то, что впрямую меняет архитектуру экономики/науки.

```text
Происхождение (Хэлган / Хивер / Кси / Чужой — LORE_COSMOLOGY_SPEC.md §1-9)
   ↓ решает, применима ли схема ниже вообще (см. §12)
Раса/линия → дефолтная Role-affinity + допуск (или нет) к Путям Силы

Именной ресурс — три яруса: bulk / strategic / кристалл Хивера (§5, §8)
   ↓ несёт Category+Tier+Role (§5, §6)
   ↓ тратится на старте
Order (перелёт / стройка / исследование / бой / дипломатия, §2-3)
   ↓ модифицируется
ModifierStack (законы, инфраструктура, раса, путь, §10)
   ↓ резолвится по ETA / мгновенно / по реакции игрока
Результат → меняет склад/карту/RoleScore
   ↓
RoleScore (§7) — ОДИН счётчик на бэкенде, ДВЕ проекции на экране:
   ├─ панель «Экономика» → уникальные юниты/постройки/законы
   └─ панель «Наука» → доступность Путей технологий (§10)
   └─ крупный порог (комбо путей) → Доктрина Воплощения (§12) → обрывает связь с Путями Силы (кроме Хаотетики)

Пути Силы (Разум/Воля/Хаотетика/Теневодство) — ОРТОГОНАЛЬНО RoleScore,
   не экономический анлок: только по крови (касание Хивера) или GM-событие,
   кристалл Хивера — потенциальный катализатор, не сырьё для стройки (§12)
```

**Экономика и Наука — разные экраны, один счётчик.** Игроку не обязательно знать, что за кулисами это одно и то же число — как ABCDEF, это внутренняя механика движка, не то, что выносится на интерфейс. Единственное общее на экране (опционально) — сами 8 иконок ролей, если показывать их одинаково в обеих панелях, чтобы связь была узнаваема, но не навязана.

Ничего не выброшено из более ранних решений — всё легло в одну структуру, использующую один словарь ролей на нескольких уровнях (ресурсы → агрегат → технологии → воплощение), при этом Пути Силы сознательно остаются вне этой экономической логики — по лору её и не должно быть.
