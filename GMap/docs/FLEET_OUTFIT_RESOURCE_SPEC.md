## 1. Цель

Раздел **Силы** уже умеет оснащать корабль/легион (`filledSlots` → бой). Каталог модулей тонкий, бой почти не читает тип оружия, а склад богатый именами руд сливается в бакеты.

Нужно одно: **полки обвеса + двухуровневая стоимость ресурсов**, без второго конструктора «как в GalCiv» и без 80 уникальных рецептов «рельсотрон MK V = конкретный камень».

Формула владельца (принята):

- у **каждого вида** есть базовая доступная стоимость ресурсов;
- ступени **T2 / T3 / T4 / T5+** привязаны к более дорогим **именным** ресурсам.

## 2. Что уже стоит в GMap

Проверено по коду, не по памяти.

### 2.1 Конструктор и UI

- UI: `GMap/src/viewer/forces/` (`ForcesDeck.tsx`, `outfitRules.ts`, `CombatCardMeta.tsx`).
- Спека раздела: `FORCES_SECTION_SPEC.md` — оснащение = главный боевой verb (`filledSlots` → `propertyCombatMult`).
- Корабль = тип корпуса (`ships.json`) + слоты + заполнение. Верфь/казармы — не этот раздел.

Слоты разведчика: `hull`, `weapon`, `reactor`, `engine`, `crew`.  
На крупных корпусах добавляются: `shield`, `armor`, `tactic`.

Требования слотов (пример, `ship.scout`):

| Слот | `require` |
|------|-----------|
| hull | `strong`, `tier >= 1` |
| weapon | `weapon`, `theater: space` |
| reactor | `energy` |
| engine | `fuel`, `theater: space` |
| crew | category `E` |
| shield (крупнее) | `shield` |
| armor (крупнее) | `strong` + `malleable` |

### 2.2 Каталог модулей

`GMap/content/core/modules.json` — **10 космос + 10 земля**.

Космос:

| id | Имя | Кат. | Тир | Свойства |
|----|-----|------|-----|----------|
| `module.space.kinetic_cannon` | Кинетическая пушка | C | 1 | `weapon`, `kinetic` |
| `module.space.light_laser` | Лёгкий лазер | D | 1 | `weapon`, `laser` |
| `module.space.missile_rack` | Ракетная кассета | C | 1 | `weapon`, `missile` |
| `module.space.plasma_projector` | Плазменный проектор | D | 2 | `weapon`, `plasma`, `weapon_amp` |
| `module.space.torpedo` | Торпеда | C | 2 | `weapon`, `missile`, `weapon_amp` |
| `module.space.chem_drive` | Химпривод | D | 1 | `fuel` |
| `module.space.ion_drive` | Ионный привод | D | 2 | `fuel`, `accelerate` |
| `module.space.fusion_drive` | Термоядерный привод | D | 3 | `fuel` |
| `module.space.screen_emitter` | Экран | D | 2 | `shield` |
| `module.space.deep_scanner` | Глубинный сканер | F | 3 | `info_store` |

Земля: винтовка / лазерный карабин / ПТ / осадный ствол / панцирь / абляция / полевой набор / орудие машины / гусеницы (+ ещё по каталогу).

Производство модулей уже завязано на здания (`buildings.json`: `module.space.kinetic_cannon`, `light_laser`, `missile_rack`, …).  
Техники уже есть: `tech.military.kinetic_guns`, `light_laser`, `missile_rail`.

### 2.3 Бой

Два независимых слоя:

1. **Роли корпуса** (`combat_matchups.json`): screen / line / capital / carrier / support / bombard + infantry / assault / garrison / armor / psi.
2. **Свойства обвеса** (`combatResolve/properties.mjs` → `propertyCombatBreakdown`):
   - `weapon_amp` → ×1.2
   - `matter_destroy` → ×1.5 и пробой щита
   - любой `shield` → ×0.6, если нет пробоя
   - сравнение **тира** оружия и корпуса
   - `psion_suppress` / `matter_destroy` как обход

**Не читает** теги `kinetic` / `laser` / `missile`. Слот `armor` в матчапе обвеса не участвует.  
Авторезолв (`combatResolve/resolve.mjs`) берёт `meanPropertyMultVsSample` против **первого** защитника.  
Карточный бой использует те же теги в `cardBattleHints.ts` (`amp`, `hull_break`, `shield_pierce`, `shield_absorb`, `hull_pierce`, `hull_resist`).

Экзотика = `matter_destroy` / `psion_suppress`, не четвёртое дерево оружия.

## 3. Решения: что берём, что не копируем

Референсы (только каркас, не контент 1:1): Galactic Civilizations, Космические рейнджеры, Stellaris, Endless Space 2.

| Берём | Не копируем |
|-------|-------------|
| Три семьи оружия + броня + щит + ПКО | Таблица GalCiv «25 размеров × 5 MK» |
| Авиация как отдельная полка (ангар / эскадрилья) | Износ и топливо Рейнджеров как отдельная бухгалтерия |
| Семья + тир, не уникальное имя ствола | Уникальный камень на каждое MK-имя |
| Экзотика как свойство пробоя, не 4-я семья | Органы кризисов / артефакты DLC как отдельные полки |
| ~12 стволов + ~9 защит на старте | Полный каталог всех четырёх игр |

ПКО можно начать **свойством**, не новым слотом. Двигатель / сканер — позже по приоритету, слоты уже есть.

Имена MK / класс H / «улучшенный» — **ступени одного типа**, не новые категории.

## 4. Единые полки обвеса

Одна сетка. В UI и контенте — эти имена, не имена референс-игр.

| # | Полка | GMap сейчас | Категория склада модуля |
|---|-------|-------------|-------------------------|
| 1 | Кинетика | `kinetic` | C |
| 2 | Луч / энергия | `laser`, `plasma` | D |
| 3 | Ракета / торпеда | `missile` | C (+ D как топливо боеголовки) |
| 4 | Авиация | роль `carrier`, отдельного модуля нет | C + E |
| 5 | Броня | слот `armor`, почти пустой | A (+ B сплавы) |
| 6 | Щит | `shield` | D |
| 7 | Перехват / ПКО / флак | **нет** | C (как кинетика) + наведение |
| 8 | Двигатель / FTL | `fuel`, `accelerate` | D |
| 9 | Сенсор | `info_store` | F |
| 10 | Утилита | реактор `energy`, экипаж E, тактика | D / E / C |

Корпус — не полка обвеса, а **класс корабля** (`ships.json`). Материал корпуса идёт в слот `hull`.

## 5. Матчап: тройка + ПКО

Задуманный треугольник (ещё не в `propertyCombatBreakdown`):

| Атака | Сильна против | Слаба против |
|-------|---------------|--------------|
| Кинетика | щиты | броня |
| Луч | броня | щиты |
| Ракеты / авиация | обходят слои (или игнорируют) | ловятся ПКО |

Экзотика (`matter_destroy`, пси) — не сторона треугольника, а **пробой / обход** на высоких тирах.

Роли корпуса (`combat_matchups.json`) остаются отдельным слоем: экран бьёт капитал иначе, чем линия. Обвес не заменяет роль.

## 6. Ресурсы: три оси

Уже в `ECONOMY_TECH_REDESIGN_SPEC.md`. Здесь — только то, что нужно обвесу.

| Ось | Что значит | Где живёт |
|-----|------------|-----------|
| **Категория A–F** | стадия производства, не полка боя | `economy_schema.json`, `map_resources.json` |
| **Тир 1–10** | мощность | `tier` |
| **Свойство / Role** | какая полка обвеса | `properties[]` |

Категории:

| Кат. | Имя | В обвесе |
|------|-----|----------|
| A | Сырьё (extracta) | корпус, броня |
| B | Материалы (materia) | сплавы, кристаллы фокуса |
| C | Промышленность (industria) | кинетика, ракеты, ПКО, ангар, корпус модуля |
| D | Энергия (energia) | луч, щит, реактор, двигатель |
| E | Биомасса (bios) | экипаж, дроид, земля; не космостволы |
| F | Знание (cognitio) | сканер, пси, экзотика |

Роли (`ECONOMY_TECH_REDESIGN` §6) ↔ полки:

| Role | Полки |
|------|-------|
| structural | корпус, броня |
| energy | реактор, луч, щит |
| offensive | кинетика / луч / ракеты |
| defensive | щит, ПКО, броня |
| mobility | двигатель |
| cognitive | сканер, пси |
| biological | экипаж, земля |
| exotic | пробой T4+ |

Сток — **именованный** `map.*` id. Bulk взаимозаменяем внутри category+tier. Strategic (соларит, блюматид, стеклосталь, вайтид, блакула, виолид, хиноварь, …) всегда явный.

Многие руды сейчас с пустым `properties: []` или клоны по тиру (железо/титан/стеклосталь все `strong`). Пока свойства пустые — в слот обвеса их не пускать как «любой B».

## 7. Правило стоимости: база + именная надбавка

Два слоя, не 80 рецептов. Совпадает с `ECONOMY_TECH_REDESIGN` §7 и с формулировкой владельца.

| Ступень модуля | Что платишь | Откуда |
|----------------|-------------|--------|
| **T1 (база)** | только bulk своей полки | любой подходящий id, `tier ≥ 1` |
| **T2** | база + 1 именной средней полки | конкретный `map.*`, `tier ≥ 3–4` |
| **T3** | база + именной выше | `tier ≥ 5–6` |
| **T4** | база + редкий / strategic | `tier ≥ 6–7` + нужное свойство |
| **T5+** | база + экзотика | F / аномалия / `matter_destroy` / пси |

База **всегда** есть: без железа / водорода / промки корабль не клепается. Дорогое — надбавка, не замена.

Семейство + тир задают свойство и минимальный тир. Именная руда — **премиум-ингредиент**, не новый тип оружия.

| Ступень | База | Надбавка |
|---------|------|----------|
| T1 | `map.energy` / `map.hydrogen` | — |
| T2 | | `map.blumatid`, `map.solari` |
| T3 | | `map.helium3`, `map.isotopes` |
| T4 | | `map.radid`, `map.zro` |
| T5+ | | `map.vaitid`, грёзный туман, `map.astral_threads` |

### 8.8 Реактор — `energy`

- T1: `map.hydrogen`, лёд, `map.energy`
- T2–3: `map.methane`, `map.biofuel`, экзогазы
- T4–5: `map.solari`, `map.helium3`, `map.isotopes`, `map.energy_minerals`
- T6+: `map.radid`, `map.zro`, `map.antimatter`

### 8.9 Двигатель — `fuel` / `accelerate`

- T1: `map.hydrogen`, `map.methane`
- T2: `map.biofuel`, замёрзшие топлива/газы
- T3: экзогазы, `map.blumatid` (`accelerate`)
- T4: `map.solari`, `map.helium3` (ион = энергия + гелий)
- T5+: `map.hyperium` (ход), `map.antimatter` (прыжок), `map.vaitid` (`corridor_open`)

### 8.10 Сенсор — F + `info_store`

- T1: малые артефакты
- T2: лунные жилы, `map.astral_threads`
- T3: гринид, `map.relics`

База всё равно C/D на корпус прибора (`map.krin` + энергия). F — только «мозги».

### 8.11 Экипаж / дроид / земля — E

T1: вода, биомасса, пища.  
T2+: лекарства, биокатализаторы, ферменты, корень дракона.  
Не в космостволы.

### 8.12 Экзотика (обход щита/брони)

Не база. Только надбавка T4+: `map.blakula` (`matter_destroy`), `map.vaitid` (`psion_suppress`), гринид, клакс, `map.relics`.  
Базовый ствол всё равно C или D T1.

## 9. Как это стыкуется со слотом

Уже есть dual path: слот пишет `{ properties, tier, theater }`, не id. Игрок кладёт конкретный сток.

| Слот | T1 принимает | T3+ хочет ещё |
|------|----------------|---------------|
| корпус | любой `strong` ≥1 | `strong` ≥ тира корпуса |
| броня | `strong` + `malleable` | то же выше тиром |
| орудие | модуль C/D **или** руда `weapon` | модуль того же семейства + именной |
| щит | `shield` | соларит / блюматид / вайтид |
| реактор | `energy` | изотопы / антиматерия |
| двигатель | `fuel` | `accelerate` на T2+ |
| экипаж | E ≥1 | — |
| сканер | `info_store` | F выше тиром |

Предпочтительный поток:

1. Верфь **производит модуль** по рецепту «bulk полки + именной».
2. В слот колоды кладётся **модуль**.
3. Руда на карточке — опция «полевая замена» (текущий dual path), не основной путь T3+.

Узкое место уже задумано: минимум тира заполненных ресурсов.

## 10. Именные специи (strategic)

Их мало, они должны быть заметны на карте. Остальные ~70 — bulk базы T1.

| Ресурс | id | Полки, куда открывает T2+ |
|--------|----|---------------------------|
| титан / стеклосталь | `map.titan`, `map.glasssteel` | корпус, броня, кинетика |
| блюматид | `map.blumatid` | броня, щит, двигатель |
| соларит | `map.solari` | луч, щит, реактор, ракеты |
| фокусирующие кристаллы | `map.focusing_crystals` | луч, ПКО |
| гелий-3 / изотопы | `map.helium3`, `map.isotopes` | реактор, луч |
| гипериум | `map.hyperium` | двигатель (дальность) |
| адамантий | `map.adamantian` | броня / кинетика верх |
| антиматерия | `map.antimatter` | луч / ракеты / реактор T5 |
| блакула | `map.blakula` | экзотика-пробой |
| вайтид | `map.vaitid` | щит-пси, коридор, экзотика |
| наниты | `map.nanites` | авиация, ремонт |
| реликты / астральные нити | `map.relics`, `map.astral_threads` | сканер, пси |

RoleScore качается с добычи той же оси (structural с `strong`, energy с `fuel`/`energy`, …) — без второй бухгалтерии.

## 11. Чего не делать

- Не вешать уникальную руду на «рельсотрон MK V» vs «гаусс». Семейство + тир. Имя — лор.
- Не пускать пищу в лазер и титан в сканер без свойства.
- Не делать T5 только из F: без A/C/D базы верфь не работает.
- Пустые `properties` на T2+ для обвеса не использовать — это снова «всё в один бакет».
- Не копировать износ/топливо Рейнджеров и сетку размеров GalCiv.
- Не плодить четвёртое дерево оружия; экзотика = свойство пробоя.
- Не хардкодить tech/module ids в UI — контент описывает себя.
- Не ослаблять экономику/бой «ради скорости» без запроса владельца.

| Теги `kinetic`/`laser`/`missile` | есть на модулях | читать в `propertyCombatBreakdown` |
| Слот `armor` | есть на крупных корпусах | участвует в матчапе vs кинетика |
| ПКО | нет | свойство или модуль C, ловит ракеты/авиацию |
| Авиация как обвес | только роль `carrier` | модуль C+E, когда понадобится |
| Рецепты модулей | здания производят модуль | база bulk + именной по тиру |
| Dual path руда-в-слот | работает | оставить как полевую замену |
| Клоны `strong` | железо/титан/стеклосталь одинаковы | вторая черта (§8 экономики) |
| Авторезолв vs первый защитник | так | отдельно, не этот спек |

Целевой объём контента на первый проход: **~12 оружия + ~9 защит**, семья+тир, без MK-имён в id.

## 13. Справочник: имена из референсов

Сжатие в полки **не выкидывает** имена — они лор и ориентир тиров. В GMap они не становятся отдельными id.

Тиры (II, III, класс H, MK V) — ступени, не новые полки. Уникальный мусор кризисов / био-органов кладётся в ту же полку.

### Корпус (класс, не обвес)

Размер: крошечный, малый, грузовой, средний, большой, огромный.  
Лёгкие: разведчик, патруль, корвет, фрегат, охотник, пикет.  
Линия: эсминец, крейсер, атакующий.  
Тяжёлые: линкор, дредноут, флагман, страж, титан, колосс, бегемот, джаггернаут.  
Особые: авианосец, координатор, пси-крейсер, колонизатор, транспорт.

### Кинетика

Пушка, масс-драйвер, рельсотрон, гаусс, автопушка, кинетический артиллерийский, сингулярный драйвер, нано-риппер, слаг, осколочное, флак (если не вынесен в ПКО).

### Луч

Лазер, тяжёлый лазер, фазер, луч, плазма, шторм, дезинтегратор, фазовый, протонный, ионный (как оружие, не привод).

### Ракета

Кассета, ракетная установка, торпеда, рой, ядерная, антиматерия-боеголовка, гравитомб.

### Авиация

Ангар, эскадрилья, ударный борт, перехватчик, бомбардировщик.

### Броня

Плиты, титановая, кристаллиновая, абляционная, нанохитин, живой металл, адаптивная.

### Щит

Экран, дефлектор, ГЗП, фазовый щит, пси-щит.

### ПКО

Точечная оборона, флак, лазерный ПКО, эскортные ракеты.

### Двигатель

Хим, ион, термояд, гипер, варп, прыжок, антиматерия.

### Сенсор / утилита

Сканер, дальность, ремонт, наниты, колониальный модуль, транспорт войск, реактор, тактика, экипаж.
