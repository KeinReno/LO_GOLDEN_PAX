# Процесс проектирования UX/UI — обязательный контракт

> Статус: **канон, обязателен к исполнению**. Дата: 2026-08-09.
> Не заменяет `UI_SYSTEMS_MASTER_SPEC.md` (парадигма/разделы) — добавляет то, чего там не хватало:
> **проверяемый контракт**, из-за отсутствия которого разделы разъехались по качеству (Экономика ↔ Наука/Двор).
> Источник диагноза: `tmp/viewer-ux-audit-v05.md` (жестовая грамматика, z-слои) + независимый UI-аудит той же
> сессии, что и `ECONOMY_TECH_REDESIGN_SPEC.md`.
> **Поэкранное целевое IA** (10 сек / 1 CTA / запреты): `VIEWER_WIREFRAME_SPEC.md` — компас комнат, не backlog;
> оркестрация фаз: `agents-roadmap/README.md`.

## Зачем этот файл

Экономика в viewer построена правильно: touch-жесты, превью до действия, единый цвет-язык. Наука и часть
Двора строились в другую волну и не сверялись с этим образцом — отсюда нативный HTML5 drag, который не
работает от касания, `window.confirm()` посреди боя, разные иконки на одно и то же действие. Это не вопрос
таланта конкретного агента — это отсутствие **проверяемого списка**, который любой агент обязан прогнать
перед тем, как считать панель готовой. Этот файл — тот список.

## Канонический словарь жестов (не изобретать новый)

Источник: `tmp/viewer-ux-audit-v05.md`, раздел «Легенда решений». Любая новая интеракция обязана лечь в одну
из этих шести строк — если не ложится, сначала расширь эту таблицу отдельным решением, не изобретай седьмой
паттерн молча.

| Паттерн | Когда | Реализация |
|---|---|---|
| **ActionRing** (long-press) | 3–6 глаголов на сущности | `ActionRing` — уже есть, переиспользовать компонент |
| **DragCard → DropZone** | перенос/назначение | хук поверх `@use-gesture/react`, см. ниже |
| **Strip / track** (drag) | дискретные тиры/значения | `TaxDragStrip.tsx` — образец |
| **List + tap** | выбор / drill-down | обычный список, без драга |
| **Кнопка** | один CTA / confirm / hotkey | `HoldButton` для необратимых действий |
| **Карточка** | только контейнер взаимодействия, не сама интеракция | — |

## Обязательные общие примитивы

Ничего из этого нельзя реализовывать «ещё раз, локально в своей панели». Если примитива ещё нет как
переиспользуемого экспорта — первая же задача, которая в нём нуждается, обязана вынести его в общее место
(`src/viewer/shared/` — завести, если ещё не существует), а не встроить внутрь своего компонента.

| Примитив | Эталонная реализация уже в коде | Статус |
|---|---|---|
| Drag-хук с touch | `useDrag` из `@use-gesture/react`, `{ pointer: { touch: true } }` — см. `RpsChain.tsx`, `TaxDragStrip.tsx` | есть, вынести в `useTouchDrag` |
| Подтверждение необратимого действия | `HoldButton` (используется в дипломатии) | есть, но не везде применяется — см. C3 |
| Ступенчатый выбор количества | `AmountSheet` (`TradeColumn.tsx`) | есть, не везде применяется |
| Статус-чип (иконка + цвет, не только цвет) | `formatStatusIcon` (Экономика, ❌/⚠) | есть, не везде применяется |
| Модальное подтверждение (не браузерное) | паттерн из `PoliciesSection.tsx` (смена доктрины) | есть, не везде применяется |

## Область действия — только `/view` (игрок), не GM-редактор

Этот контракт покрывает `src/viewer/**` — поверхность игрока. **GM-инструментарий (`src/editors/gm/**`,
`src/editors/RpChat.tsx`, `src/editors/GmCatalogEditor.tsx` и т.п.) в область действия не входит.** Это
намеренное решение, не пропуск: GM-редактор — desktop-only, мышь+клавиатура, административный по природе
(мастер редактирует каталоги, а не проживает историю), и обоснование запретов ниже (touch-first, сохранение
погружения) там не применимо. Конкретно: `window.confirm()` в `GmQuestCatalogShell.tsx:163`,
`GmCatalogEditor.tsx:321`, `RpChat.tsx:464` (удаление записи каталога/RP-реплики мастером) — оставить как
есть, это нормальный паттерн для админ-действия «удалить», не повод унифицировать под геймплейный контракт.
Если позже понадобится отдельный UX-стандарт для GM-инструментов — заводить отдельным документом, не
расширять этот молча.

## Прямой запрет (правило, не рекомендация) — для `src/viewer/**`

Ни одна новая или правящаяся панель игрока не имеет права использовать:

- `window.confirm()` / `window.alert()` / `window.prompt()` — только themed-модалка или `HoldButton`.
- Нативный HTML5 Drag-and-Drop (`draggable`, `onDragStart`, `e.dataTransfer`) — не работает от касания на
  телефоне. Только `useTouchDrag` (см. выше).
- Голый `<select>`/`<input type="number">` там, где выбор — из короткого перечисляемого набора или суммы —
  используй `Strip`/`AmountSheet`. Исключение: `CourtPanel.tsx` advisor-select — короткий перечислимый список
  без пространственной семантики, разрешено оставить как есть.
- Разные иконки для одного и того же действия / одна иконка для разных действий в одной панели (пример
  нарушения: «Купить»/«Продать»/«На биржу» в `StockpileSection.tsx` — все три сейчас на иконке `Store`).

## Цвет — семантика отдельно от бренда

- **Семантические** (не переопределяются темой): зелёный = избыток/доход, красный = дефицит/расход, жёлтый =
  предупреждение/узкое место. Всегда дублируются иконкой/текстом — цвет никогда не единственный сигнал
  (см. `formatStatusIcon`). Нарушение сейчас: `ResearchMatrix.tsx` (`is-affordable`/`is-queueable`,
  `app.css:11100/11104`) — различие только по цвету рамки, без иконки. Почини при следующем касании файла.
- **Брендовый/имперский акцент** (циан) — обязан быть токеном `--accent-imperial` (сейчас литерал `cyan`
  захардкожен ~20 раз в `app.css`, например `:7452, :12095, :13573, :13680`). Заводить токен и переносить
  использования — не обязательно одной задачей, но каждое новое использование обязано идти через токен, не
  добавлять 21-й хардкод.
- Карта: `ORDER_ARROW_COLORS`, `ACTIVITY_COLOR`, `POI_TINT` — язык угрозы/статуса, не бренда. Должен быть
  идентичен во всех темах карты (`classic`/`imperial`/`holo`, см. `map-visual-redesign/00-OVERVIEW.md` §5) —
  никогда не переопределять per-theme.

## Правило двух шагов (конкретно, не абстрактно)

От «игрок увидел проблему» до «игрок совершил действие» — максимум 2 касания/клика. Пример эталона:
`OverviewSection.tsx` «Внимание» — дефицит показан с одной кнопкой действия рядом. Пример нарушения:
`BudgetSection.tsx` — проп `focusReason` для перехода «клик по расходу → отфильтрованный бюджет» написан,
но ни разу не передан вызывающим кодом (`EconomyPanel.tsx:305`, `OverviewSection.tsx` донат без
`onSelectReason`) — переход из спеки не работает, хотя выглядит реализованным. Проверяй не только «код
существует», но и «код вызывается».

## Тач-цели

Минимум 40px по меньшей стороне для любого интерактивного элемента на мобильном лейауте. Нарушение сейчас:
`.eco-stock-card__btn` (`app.css:14930`) — 28px, до 6 штук в одной карточке склада.

## Definition of Done для любой панели/секции

Перед тем как считать задачу над панелью закрытой, агент обязан пройти этот чек-лист и явно перечислить
результат в `tmp/summary-{timestamp}.json`:

1. Все интерактивные элементы используют паттерн из «канонического словаря жестов» — не изобретён седьмой.
2. Ни одного `window.confirm/alert/prompt`, ни одного нативного HTML5 DnD.
3. Каждый статус закодирован цветом **и** иконкой/текстом, не только цветом.
4. Циан — через токен, не литерал (если панель трогает цвет).
5. Все заявленные в спеке переходы «клик → другая панель» реально вызываются (проверь, что проп передан, а
   не только объявлен).
6. Тач-цели ≥ 40px на мобильном лейауте.
7. Компонент не пересёк ~400 строк без явного решения его декомпозировать (если пересекает — задача не
   закрыта, пока не разбит либо не обоснованно оставлен).
8. `npm run smoke`, `npm run smoke:tick` проходят.
