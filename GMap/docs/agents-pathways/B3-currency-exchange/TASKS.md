## Цепочка задач

### T3.1. Формула курса через общий номинал

Не считать N² пар вручную. Ввести один расчётный номинал (`fx.exchange_credit` — не настоящая валюта,
просто единица расчёта). Для каждой `fx.*`-валюты курс к номиналу:

```
rate(fx.X → exchange_credit) = base(1.0) 
    × (резервы_анкора / референс_резерв)^w1 
    × (добыча_анкора_за_ход / референс_добыча)^w2
```

`референс_резерв`/`референс_добыча` — среднее по всем фракциям с назначенным `treasuryPeg` (пересчитывать
раз в N ходов, не каждый тик — см. T3.3 про инерцию). Курс `fx.A ↔ fx.B` = `rate(A→credit) / rate(B→credit)`.
Веса `w1`, `w2` — подбери разумные (например `0.6`/`0.4`), задокументируй выбор в summary.

### T3.2. Инерция — не обнулять курс одним рейдом

Курс не пересчитывается мгновенно от разового изменения резерва/добычи. Храни скользящее среднее (EMA, окно
~5-10 ходов) резервов/добычи анкор-ресурса per фракция, считай курс от EMA, не от мгновенного значения.

### T3.3. Реализовать `computeFxRates()` в новом модуле или `marketRates.mjs`

Функция, вызываемая раз в тик (из `runEconomyTick` или отдельным шагом `processTurn.mjs`), считает курсы всех
`fx.*`-валют друг к другу через номинал (T3.1+T3.2), пишет в `data/market-rates.json` в **существующем**
формате `{ rates: [{ pair, buy, sell, note? }] }`, чтобы `getEffectiveMarketRates()` подхватил их без
изменений в `lookupMarketRate`. GM-оверрайд (ручная правка через `GmMarketRatesEditor`) остаётся приоритетнее
расчётных — не затирай ручные строки, если GM их выставил (используй `note`/отдельный флаг, чтобы отличать
расчётные от ручных пар).

### T3.4. Защита от манипуляции объёмом

Курс считается **только** от резервов+добычи (макропоказатели), никогда от объёма сделок на самой бирже —
это уже заложено в T3.1, просто явно убедись, что нигде не завязываешь курс на `marketConvert`-историю.

### T3.5. UI: показать, что курс расчётный

В `GmMarketRatesEditor.tsx` — пометить строки, пришедшие из `computeFxRates()`, как "авто" (только для чтения
по умолчанию, с кнопкой "переопределить вручную"). Не обязательно делать полноценный график курса за N ходов
в этой задаче (можно оставить как TODO/заглушку) — минимум: таблица текущих `fx.*`-пар с пометкой источника.

### T3.6. Миграция и тесты

Если `data/market-rates.json` не существует — `computeFxRates()` создаёт его при первом тике. Прогони
`npm run smoke:tick`. Проверь вручную: `marketConvert(factionId, "fx.belator_solarit", "fx.aphel_ilir", ...)`
больше не возвращает `rate_missing`.

## DoD

- Курс между любыми двумя `fx.*`-валютами фракций с назначенным `treasuryPeg` вычисляется без ошибки
  `rate_missing`.
- Курс меняется от изменения резервов/добычи анкор-ресурса, но не обнуляется мгновенно (инерция работает).
- GM по-прежнему может вручную переопределить пару через `GmMarketRatesEditor`.
- `npm run smoke:tick` проходит.
