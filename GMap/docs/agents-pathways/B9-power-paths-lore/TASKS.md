## Цепочка задач

### T9.1. Пометить существующие расы полем `powerPath`

Добавь `powerPath?: ("mind" | "will" | "chaos" | "shadow")[]` только тем 4 расам, где уже есть прямое
основание в данных:
- `race_psionic` → `["mind"]` (текущий плейсхолдер для Разум-псионики, см. контекст выше про то, что это
  вероятно будущие Эланы)
- `race_human` → `["will"]` (по лору — Воля получена людьми на Терриале)
- `race_hybrid.human_psionic` → `["will", "mind"]` (мост, кандидат на будущую Хаотетику — **не** ставь
  `"chaos"` сейчас, это требует отдельного лорного решения автора, не додумывай)
- `race_hybrid.lord_dust_psionic` → `["mind"]`

Остальным 13 расам поле не добавляй (значит "нет доступа" по умолчанию — отсутствие поля, не пустой массив).

### T9.2. Минимальный набор эффектов (иллюстративный, не полная система)

Добавь в `effects.json` 2-3 эффекта, по одному на демонстрацию каждого типа воздействия — не полное дерево
способностей:
- `power_mind_strike` — боевой эффект (урон/дебафф цели), доступен только фракциям с `powerPath` включающим
  `"mind"`. Вешается через обычный `ModifierStack`, канал вида `power:mind`.
- `power_will_sway` — дипломатический/лояльностный эффект (снижение лояльности вражеской системы или
  влияние на переговоры), доступен при `"will"`.

Не реализуй Хаотетику/Теневодство эффектами в этой задаче — только зафиксируй их в `powerPath`-словаре типов
как валидные значения enum, без конкретного контента (задел на будущее).

### T9.3. Флаг разрыва при доктрине воплощения (задел, не реализация)

Доктрины Воплощения (Кибернетика/Синтетика/Мехинарии) — не в этой волне вообще (см. `README.md`). Но
добавь в схему `powerPath`-записи (или рядом) поле-заметку `severedByEmbodiment: true` для `"mind"`/`"will"`
и `false` для `"chaos"` — просто данные на будущее, никакой логики проверки эту задачу не пиши, доктрин
воплощения ещё не существует в коде.

### T9.4. GM-инструмент: "касание Хивера" (дать Путь Силы фракции без него)

Новый intent (`content/core/intents.json`), доступный **только мастеру** (по аналогии с существующими
GM-only intents/эндпоинтами в `server/api.mjs`, посмотри на паттерн `X-Master-Token`) —
`intent.gm.grant_power_touch`: аргументы `{ factionId, powerPath: "mind"|"will"|"chaos"|"shadow" }`,
эффект — добавляет значение в `powerPath` расы/фракции (реши, куда логичнее — на расу глобально или на
конкретную фракцию, если раса используется несколькими фракциями; вероятно на фракцию, т.к. "касание" — это
разовое историческое событие для конкретного народа, не переписывание расы целиком в реестре контента).
Минимальный UI — не обязателен в этой задаче, если есть уже существующая GM-консоль/Atelier-панель, добавь
туда одну кнопку/форму, не создавай новый экран с нуля.

### T9.5. Явно НЕ делать (чтобы не превратить в скоуп-крип)

- Не считать RoleScore или что-либо накопительное для путей Силы — это противоречит самой идее (см. контекст).
- Не создавать корабли/юниты/постройки под эти пути в этой задаче.
- Не трогать `role_milestones.json`/`civic_paths.json` (B2/B6) — это другая система.
