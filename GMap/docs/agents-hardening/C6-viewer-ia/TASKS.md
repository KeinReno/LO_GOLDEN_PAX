## Цепочка задач

### T6.1. Док: тиры primary / secondary / non-room

Сейчас на desktop цифры 1–9 смешивают рабочие комнаты, Штаб, Кодекс; Двор без digit; RP — float (ок).

Сделай IA по wireframe:

| Тир | Поведение |
|---|---|
| Primary | Карта, Силы, Экономика, Наука, Дипло — всегда видимые слоты дока + стабильные hotkeys |
| Secondary | Биржа, Квесты, Двор — в доке **или** в «Ещё», но **Двор обязан получить hotkey или явный слот** (сейчас P1 в audit) |
| Non-room | Штаб — hub/attention (не «равная» рабочая комната рядом с Наукой); Кодекс — справка; RP — float на desk / immersive на mobile (уже так — не ломай) |

Конкретная раскладка цифр — на твоё усмотрение, задокументируй таблицу hotkey→view в комментарии рядом с
`dockViewFromDigit` в `ViewerPage.tsx`. Mobile primary: Карта · Силы · Эконом · Наука · RP + «Ещё» с бейджами
(wireframe A4) — если текущий mobile primary другой, приведи к этому, не оставляя Экономику только в «Ещё»
как единственный путь.

**Не** добавляй новые `PlayerView` id без необходимости.

### T6.2. Штаб = «утро за столом»

`PlayerHqHome` уже роутер — усили по wireframe §C, **без** возврата налогов/FlowPanel/DragCard:

1. **Внимание ≤5** — каждый пункт = глагол («Открыть дефицит», «Ответить на сделку»), не только ярлык.
2. Один источник с Alert FAB: либо общий builder (`buildViewerAlerts` / attention helper), либо явный
   импорт одних и тех же правил — не два расходящихся списка.
3. `onOpenEconomyPolicies` (или аналог) **обязан** открывать Экономику на секции `policies`, не дефолтный
   overview — проверь цепочку в `ViewerPage.tsx`.
4. Сводка державы — коротко (казна/якорь, ОД, сила, опц. RoleScore-лидер если данные уже есть после B2).
   Без редакторов.
5. Проверь CSS классов HQ (`hq-command*`, `hq-outliner`) — нет «невидимых» блоков без правил в `app.css`.
