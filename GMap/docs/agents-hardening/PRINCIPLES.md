# Общие принципы волны C (укрепление)

> **Перед тем как начать любую задачу волны C — физически открой и прочитай `../agents/PRINCIPLES.md` и
> `../agents-pathways/PRINCIPLES.md` целиком.** Пункты 1–12 ниже — не пересказ, а ссылка по номеру: если ты
> не откроешь оба файла, ты прочитаешь только 13–17 и пропустишь половину нерушимых принципов проекта. Это
> не формальность — «сервер = единственная правда», «всё новое через ModifierStack», «контент — в JSON-паках»
> (пп. 1, 2, 4 волны A) применимы к каждой задаче C1–C6 не меньше, чем новые пункты ниже.

Пункты 1–10 — те же, что у волны A (`../agents/PRINCIPLES.md`), не дублируем произвольно. Пункты 11–12 —
те же, что у волны B (`../agents-pathways/PRINCIPLES.md`), тоже без изменений: «категория ≠ хранилище» и
«не расширять пилот без разрешения» применимы и здесь, если задача трека C случайно касается тех же файлов.
Пункты 13–17 — новые, специфичные для волны C.

## 13. Любая запись состояния — атомарна

Никакого прямого `fs.writeFileSync` на живой путь состояния кампании. Пиши во временный файл рядом
(`<path>.tmp-<random>`), затем `fs.renameSync` на целевой путь. Относится к `server/db/storeAdapter.mjs`
(`fileBackend().writeJson`), и к любому месту, которое сейчас пишет мимо адаптера напрямую (см. C1.T1.5).

## 14. Ошибка чтения контента/состояния — громкая, не молчаливая

Если `JSON.parse` падает на любом файле контента или состояния — не возвращать `{}`/фолбэк молча. Кидать
исключение с именем файла в сообщении (сервер логирует и, если есть канал — показывает GM), либо как минимум
`console.error` с явным префиксом `[CONTENT_PARSE_FAIL]`/`[STATE_PARSE_FAIL]`, чтобы это было grep-абельно.
Причина: то, что выглядит как «фронтенд сломался», на практике иногда — тихо опустевший каталог контента.

## 15. UX — только через общий контракт

Любая новая или правящаяся панель обязана пройти `../UX_UI_DESIGN_PROCESS.md` целиком (Definition of Done) —
включая то, что этот файл прямо запрещает (`window.confirm`, нативный HTML5 DnD, голый `<select>` там, где
есть паттерн получше). Не изобретать локальную альтернативу уже существующему общему примитиву.

## 16. Контент остаётся в JSON — в БД только runtime-состояние кампании

`content/core/*.json` (расы, технологии, здания, юниты, бой) не переносится в SQLite ни частично, ни
полностью — он редко пишется, git-diffable, уже правильно устроен как плоский словарь `id → определение`.
В БД (см. C4) идёт только высокочастотное runtime-состояние: гроссбух, приказы, столкновения, метаданные
хода. Если задача сомневается, куда класть новую сущность — правило: «пишется ли это чаще, чем раз в
сессию GM?» Да → БД. Нет → JSON-пак.

## 17. Расширять опцией, не заменять

По образцу `map-visual-redesign` (`classic` остаётся дефолтом, новые темы — опция) — ни одна задача этой
волны не имеет права снести рабочую подсистему и написать новую версию с нуля. Только точечный фикс внутри
существующей логики, либо новый параллельный, переключаемый слой поверх неё. Если задаче кажется, что
«проще переписать заново» — это сигнал остановиться и обсудить с человеком, не решать самостоятельно.
