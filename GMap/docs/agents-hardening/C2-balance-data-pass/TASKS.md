# Agent C2 — Балансный проход по данным (только JSON, без кода)

> Ты работаешь над проектом LO_GOLDEN_PAX / GMap. Это чисто контентная задача — правки JSON в `content/core/`,
> без единой строки кода в `server/`/`src/`. Не пересекается файлами ни с одним другим треком волны C, с
> волной B или с map-visual-redesign — можно выполнять в любой момент, параллельно чему угодно.

## Принципы (нерушимые)

См. `../PRINCIPLES.md` (1–17). Особо: раса/трейт получает бонус — обязана получить сопоставимый по весу
минус (тот же принцип, что уже реально соблюдается в `races.json`, см. T2.4/T2.6).

## Контекст

Независимый аудит содержимого нашёл конкретные, посчитанные на реальных числах места, где баланс — не
«RPS-треугольник», а «просто сильнее». Ниже — не мнение, а результат чтения таблиц.

## Файлы

`content/core/combat_matchups.json`, `content/core/buildings.json`, `content/core/units.json`,
`content/core/ships.json`, `content/core/races.json`, `content/core/economy_balance.json`,
`content/core/faction_traits.json`.

`tmp/analyze_balance.mjs` — существующий скрипт дампа зданий T1-T3 и юнитов/кораблей по тирам/статам/апкипу.
Расширь его (не пиши новый с нуля), если нужен дамп для проверки правок ниже — добавь секцию под
`combat_matchups.json`/`economy_balance.json`, если такой ещё нет.

## Цепочка задач

### T2.1. `combat_matchups.json` — роль `psi` не имеет контрхода

Строка `"psi"` атакует `infantry`/`assault`/`garrison`/`armor` на ≥1.05 (1.2/1.15/1.1/1.05), ни одна не бьёт
`psi` в ответ выше 1.0 (0.85/1.0/0.9/0.95). Добавь минимум одной роли реальный контр (≥1.05 против `psi`) —
кандидат: `garrison` (укреплённая позиция логично контрит психионику лучше остальных) или новая
контр-характеристика, если роль это предполагает. Задокументируй выбор одной строкой комментария в JSON
(поле `_note`, если такое уже используется в файле, иначе не добавляй новых полей — просто выбери
существующую роль).

### T2.2. `combat_matchups.json` — роль `armor` почти доминирует

`armor` бьёт `infantry`/`assault`/`garrison` на 1.3/1.1/1.2, получает в ответ только 0.75/0.9/0.8; единственный
чек — уже сама доминирующая `psi` (0.95 vs 1.05, см. T2.1). После фикса T2.1 перепроверь: даёт ли новый контр
`psi` также непрямой баланс для `armor`, или нужен отдельный контр внутри «мундane»-четвёрки
(`infantry`/`assault`/`garrison`/`armor`)? Если после T2.1 `armor` всё ещё не имеет ни одного реального
противодействия среди этой четвёрки — добавь его аналогично T2.1.

### T2.3. `combat_matchups.json` — класс `capital` без контрхода

Против `capital`: `screen` 0.7, `line` 0.85, `carrier`/`bombard` 0.9 — никто не превышает 1.0. `capital`
атакует `line` на 1.15, `carrier` на 1.05. Восстанови треугольник `screen → capital → line → screen`
(классическая naval RPS): подними `screen` против `capital` выше 1.0 (кандидат: 1.1–1.15, чтобы screen был
реальным контром тяжёлому классу), сохрани текущее преимущество `capital` над `line`, и `line` над `screen`
(если такого пока нет — добавь его тоже, иначе треугольник не замкнётся).

### T2.4. `mega.archive.belator` / `mega.gate.damyl` — супернаборы без платы

`buildings.json:2727-2766` (`mega.archive.belator`, база `cognitio.archive`) наследует стоимость базового
здания без изменений и добавляет `unlock_tech_tier F→10` (на тир дальше generic) плюс перманентный `ap_add
+1` (бюджет всего 9 ОД/ход) — бесплатно поверх. `buildings.json:2693-2726` (`mega.gate.damyl`) аналогично, плюс
требует расу `damilian`, которой нет в `races.json`. Два фикса: (а) добавь реальный компромисс обоим зданиям
— либо повышенная стоимость (`cost_mult` по аналогии с расовыми вариантами), либо `upkeep_effects` с
постоянным расходом, соразмерным ценности бонуса; (б) для `mega.gate.damyl` — либо создай минимальную запись
расы `race_damilian` в `races.json` (по шаблону из `UI_SYSTEMS_MASTER_SPEC.md §8.6`, с `balanceBudget`
суммой в 0, как у всех существующих рас), либо убери расовый лок, если раса не планируется в ближайшей волне.

### T2.5. `race_belator`/`race_human` — бонус без минуса в таблице юнитов/кораблей

`units.json`/`ships.json`: общая для всех записей 7-расовая таблица `raceVariants` (повторяется без изменений
на каждой записи, например `:65-113` = `:175-223` = `:286-334` и т.д.). Внутри неё `race_synth`/`race_karned`/
`race_psionic`/`race_swarm`/`race_voidborn` парuют бонус с минусом; `race_belator` (`defense×1.15`/
`armor×1.15`) и `race_human` (`damage×1.05`) — только бонус. Добавь обеим сопоставимый по весу минус (не
обязательно тот же стат — например, `race_human damage×1.05` можно уравновесить небольшим `hp×0.95` или
`speed×0.95`; `race_belator defense×1.15` — например `damage×0.95`). Правь **один раз** в общей таблице —
она переиспользуется на каждой записи буквально, изменение одной копии не распространится на остальные
автоматически, найди и поправь все вхождения (`grep -n "race_belator" content/core/units.json
content/core/ships.json`).

### T2.6. `race_nagaar` — единственная незабюджетированная раса

`races.json:207-242`, `trait.nagaar.titular` (`loyalty_add +2`) имеет `balanceBudget: 0.5` без компенсирующего
отрицательного трейта — единственное исключение среди 16 остальных рас, где сумма строго 0. Добавь второй
трейт с `balanceBudget: -0.5` (любой тематически подходящий минус — например, штраф к чему-то, что логично
для этой расы по её `origin`/`xenorelations`), чтобы сумма сошлась в 0, как у всех остальных.

### T2.7. `economy_balance.json` — провал тира 2 и обрыв Era3→Era4

`:101` (`metalByTier`) / `:109-112` (`yieldFlatByTier`): T2 — единственный тир, где отношение выход/цена хуже
соседних (0.091 против 0.125 у T1 и 0.133 у T3). Подними `yieldFlatByTier[2]` с 1 до 2 (тогда отношение
станет ~0.18, ближе к соседям, поправь итоговое число под желаемую кривую, не обязательно ровно 2 — главное
убрать провал). Отдельно: средняя стоимость технологии по эрам (посчитана из `technologies.json`) скачет
Era3→Era4 в ×3.23, тогда как остальные переходы держатся в ×1.4–2.0. Сгладь — либо снизь стоимости самых
дорогих Era4-технологий ближе к ×2 от Era3, либо (если скачок осознан как «стена входа в эндгейм») задокументируй
это явно в `docs/BALANCE_BASELINE_SPEC.md` как правило, а не оставляй необъяснённым числом.

### T2.8. `faction_traits.json` — `balanceBudget` не соответствует весу эффекта

`:53-63` (`trait.citizen_militia`, defense×1.2 за move_cost×1.1) оценен в `-1` (худший уровень); `:121-132`
(`trait.psi_doctrine`, unlock_property + два отдельных −15%-штрафа производства) оценен в `+1`. Пересчитай
`balanceBudget` всех трейтов в этом файле по той же строгой логике, что уже реально работает в `races.json`
(сумма эффектов трейта, не интуитивная оценка) — ориентируйся на готовую арифметику `races.json` как эталон
для копирования метода, не изобретай новую шкалу.
