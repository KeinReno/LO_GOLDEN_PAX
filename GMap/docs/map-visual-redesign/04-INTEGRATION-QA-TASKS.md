# 04 — Сведение треков и финальная приёмка

> Предпосылка: `01` замёржен, `02-IMPERIAL-CARTOGRAPHY-TASKS.md` и `03-HOLOGRAPHIC-TABLE-TASKS.md` оба выполнены (каждый в своём файле `imperialTheme.ts`/`holoTheme.ts`). Этот документ — для того, кто освободится первым, или для отдельного прохода после обоих треков.

---

## Задача 1 — Реестр тем: включить обе реализации

В `src/renderers/styles/index.ts` заменить временные заглушки (`01-SHARED-FOUNDATION-TASKS.md`, Задача 9) на реальные реализации:
```ts
import { classicTheme } from "./classicStyle";
import { imperialTheme } from "./imperialTheme";
import { holoTheme } from "./holoTheme";

export const MAP_THEMES: Record<MapStyleId, MapTheme> = {
  classic: classicTheme,
  imperial: imperialTheme,
  holo: holoTheme,
};
```
Это единственная строка кода, которую физически трогают оба трека — если оба агента сделали PR/диф независимо, здесь может быть тривиальный конфликт (две строки импорта + две строки в объекте) — смёржить руками, оба изменения аддитивны и не пересекаются логически.

**Acceptance:** переключение всех трёх стилей в UI (редактор + оба места viewer'а) даёт три визуально разных карты на одних и тех же данных.

## Задача 2 — Плашки иконок: свести обе правки в `mapIconSprites.ts`

Если оба трека независимо правили `MapIconOverlay`/plates-логику (`02` Задача 6, `03` Задача 7) — свести в единый `switch (theme.iconPlateStyle)`/`if`-цепочку с тремя ветками (`classic` — как есть сегодня без изменений, `imperial-rim`, `holo-outline`). Проверить, что сами спрайты-иконки (`ICON_PATHS`) и их тинты (`POI_TINT`/`ACTIVITY_TINT`) не были случайно задеты ни одним из треков — это вне скоупа обоих (см. `00-OVERVIEW.md` §5).

**Acceptance:** одна функция плашек с явным переключением по теме, без дублирования кода между ветками там, где это возможно (общая геометрия плашки, разный только stroke/fill).

## Задача 3 — Инвалидация кеша при смене темы

Проверить (см. `01-SHARED-FOUNDATION-TASKS.md` Задача 9, примечание про fingerprint) — переключение стиля прямо во время сессии (без reload) на плотной карте:
- [ ] Территории/границы/системы полностью перерисовываются новым стилем, без «призраков» геометрии предыдущего стиля.
- [ ] Проверить конкретно `territoryFpRef` (или его аналог после рефакторинга) — в строке фингерпринта обязан участвовать `mapStyle`.
- [ ] Проверить кеш подписей/эмблем (`textCache`/`emblemCache` в `drawFactionLabels`/`drawCapitalEmblems`) — если направление А добавляет плашку под текст, а направление Б — HUD-скобки, при смене темы эти доп. элементы не должны залипать друг на друге (например, золотая плашка от `imperial` не должна визуально суммироваться с HUD-скобками `holo`, если оба рисуются в общий `labels`-контейнер, а не пересоздаются).

**Acceptance:** 5 переключений подряд (`classic → imperial → holo → imperial → classic`) без визуального мусора и без роста потребления памяти (проверить через DevTools Performance/Memory, если есть подозрение на утечку `Sprite`/`Text` в пулах).

## Задача 4 — Полный цветовой аудит по кампании

Пройтись по всем фракциям в `public/campaigns/lo_golden_pax.json` (`"factions": [...]`), для каждой — включить обе новые темы поочерёдно и проверить:
- [ ] Заливка/граница/маркер фракции не сливаются с фоном (`TABLE.void`, `drawTableFx.ts`) — особенно риск для очень тёмных `color` (проверить, есть ли такие в реальных данных).
- [ ] Две соседние по территории фракции не оказываются визуально неразличимы (случайное совпадение хешей цвета) — если находится такая пара, это сигнал ГМу поправить `color`/`systemColor` вручную через `Редактор державы`, **не** повод городить в рендере автокоррекцию контраста (см. `00-OVERVIEW.md` §3 — цвета фракции остаются источником истины как заданы, тема их не подменяет).
- [ ] Задокументировать (просто список в комментарии к PR/задаче) все найденные проблемные фракции — не чинить данные кампании молча внутри этой задачи, если это не входило в скоуп.

**Acceptance:** список фракций проверен, проблемные случаи (если есть) переданы как отдельный пункт ГМу/дальше по процессу, не исправлены «на автомате» в рендере.

## Задача 5 — Перф-прогон

На кампании с максимальным числом систем/фракций (взять `lo_golden_pax.json` как есть, это боевая кампания — не собирать синтетическую):
- [ ] `perfMode`: Суперлайт/Лайт/Качество/Максимум/Кино × `mapStyle`: classic/imperial/holo — 15 комбинаций, зафиксировать FPS (DevTools Performance или счётчик, если он уже есть в дебаг-панели проекта) хотя бы приблизительно.
- [ ] `imperial` и `holo` не должны быть медленнее `classic` на том же тире — по конструкции (меньше слоёв заливки) они обязаны быть дешевле или как минимум не дороже. Если дороже — искать лишний draw-call (частая причина: забытый цикл колец, скопированный по инерции из старого `drawTerritoryGlow`).

**Acceptance:** зафиксированные цифры/наблюдения приложены к финальному отчёту, регрессий по FPS относительно `classic` нет.

## Задача 6 — Итоговое визуальное сравнение

Скриншот одного и того же сектора (тот же кусок карты) в трёх стилях подряд, рядом с исходным мокапом-питчем (ссылка в `00-OVERVIEW.md`) — подтвердить, что реализация действительно передаёт задуманный язык, а не «технически соответствует описанию, но выглядит иначе». Если расхождение существенное — это повод вернуться в `02`/`03`, а не тихо принять как есть.

- Нужна ли деривация цвета (`01-SHARED-FOUNDATION-TASKS.md`, Задача 3, опциональная) — оценивается по факту после Задачи 4 этого файла (цветовой аудит): если реальные однослотовые фракции выглядят приемлемо и без неё — можно не делать вовсе.
