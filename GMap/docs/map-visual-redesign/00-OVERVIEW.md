# Визуальный редизайн карты — общий план

> Папка: `GMap/docs/map-visual-redesign/`
> Статус: план к реализации, код не тронут.
> Контекст возник из дизайн-ревью текущего рендера карты (Pixi.js, `src/renderers/MapCanvas.tsx`) и питча трёх альтернативных визуальных языков. Мокапы направлений (для референса, не для копирования пикселей): https://claude.ai/code/artifact/8ac30c5c-8b43-450f-9490-8124b5dd666b

## 1. Проблема

Текущий рендер территорий и систем визуально шумный при плотной группе систем:

- `drawTerritoryGlow` (`src/renderers/drawMapIcons.ts:1108-1189`) кладёт **4–5 полупрозрачных концентрических эллипсов на каждое ядро блоба фракции** (`rings = [{rx: r*1.9,...}, {rx: r*1.55,...}, {rx: r*1.25,...}, {rx: r*1.05,...}]`, плюс пятое кольцо в `cinematic`-режиме).
- `drawSystemGlyph` (`src/renderers/drawMapIcons.ts:510-733`) рисует **отдельное кольцо обитаемости** на каждой системе (строки ~541-562) плюс 3-слойное свечение вокруг звезды у обычных систем (~647-660).
- При соседних системах эти кольца перекрываются и сливаются в мутное «зелёное облако» — визуально неотличимое от «токсичной зоны».
- Иконки событий (бой/торговля/угроза/квест) рисуются россыпью прямо поверх подсветки, разными пиктограммными языками, без общей плашки.
- Единственное место с продуманной айдентикой — экран входа во viewer (`ViewerPage.tsx`, засечный шрифт Cinzel, золото `#c9a227`/`#e8c547`) и отчасти уже готовая «двойная золотая окантовка» в `drawTerritoryBorders` (`drawMapIcons.ts:1192-1220`) — но это не продолжается в остальной карте.

## 2. Решение

Вместо одного нового языка — **два альтернативных, переключаемых пользователем визуальных языка карты**, оба на общей геометрии/данных:

- **A. Имперская картография** — статичный, «иллюминированный звёздный атлас». Продолжает то, что уже есть (золото, засечка на входе, двойная окантовка в `drawTerritoryBorders`). Один спокойный слой заливки территории вместо стопки колец, розетка вместо кольца-мишени у систем.
- **Б. Голографический стол** — кинетичный, каркасный HUD. Буквализирует то, чем интерфейс уже называет карту («Live-стол», «стол брифинга»). Тонкий каркас территории, гранёные узлы систем, импульс света по линиям снабжения.

Обе схемы переключаются как уже существующий `perfMode` (Суперлайт/Лайт/Качество/Максимум/Кино) — живут рядом с ним, не вместо него.

## 3. Жёсткое требование пользователя — ЦВЕТ ФРАКЦИЙ

**Цветовая индикация государств в обеих схемах обязана использовать цвета, заданные в самом государстве, а не новую придуманную палитру.**

В `Faction` (`src/state/types.ts`, ~строка 816) уже есть 5 цветовых полей:

```ts
color: string;           // обязательное, основной/легаси цвет
borderColor?: string;    // цвет границы территории
fillColor?: string;      // цвет заливки территории
systemColor?: string;    // цвет системных маркеров/ауры владения
nameColor?: string;      // цвет подписи названия
nameFont?: string;       // шрифт подписи
```

и готовые резолверы в `src/state/territory.ts`:

```ts
export function resolveFactionFill(f: Faction): string { return f.fillColor || f.color; }
export function resolveFactionBorder(f: Faction): string { return f.borderColor || f.color; }
export function resolveFactionSystemColor(f: Faction): string { return f.systemColor || f.color; }
export function resolveFactionNameColor(f: Faction): string { return f.nameColor || "#e8c547"; }
export function resolveFactionNameFont(f: Faction): string { return f.nameFont || "Cinzel, Times New Roman, serif"; }
```

Эти поля редактируются ГМом напрямую в `src/editors/PolityEditor.tsx` (`ProfileTab`, ~строки 467-531) через нативные `<input type="color">`, с кнопкой «Сбросить к основному цвету».

**Правило для обеих реализаций (Имперская картография и Голо-стол): всегда читать цвет через `resolveFactionFill/Border/SystemColor/NameColor`. Никогда не заводить отдельную фиксированную палитру фракций для темы.** Единственные цвета, которые НЕ являются цветом фракции и должны остаться фиксированными константами бренда/семантики — см. §5 «Не трогать».

Проверено на реальных данных кампании (`public/campaigns/lo_golden_pax.json`): большинство государств (Белатор `#ffd500`, Федерация `#4ec4d4`) задают только `color` — остальные 3 слота падают на fallback. Только часть (например, Карнед) задаёт все 4 слота вручную. Это значит: **в типовом случае заливка/граница/маркер системы у фракции будут одного и того же цвета** — это не баг реализации, это текущее состояние данных. См. `01-SHARED-FOUNDATION-TASKS.md` задачу про опциональный (не обязательный) helper вывода палитры — он **только** заполняет незаданные слоты мягким производным цветом от базового `color`, никогда не переопределяет то, что ГМ задал явно.

## 4. Архитектура

Новое поле в `MapViewModel` (`src/renderers/MapCanvas.tsx`), по образцу уже существующих `perfMode`/`graphics`:

```ts
mapStyle?: "classic" | "imperial" | "holo";
```

Новая папка `src/renderers/styles/`:

```
src/renderers/styles/
  mapTheme.ts        — общий интерфейс MapTheme + MapStyleId + резолвер
  classicStyle.ts     — ТЕКУЩЕЕ поведение, вынесенное как есть (безопасный фолбэк)
  imperialTheme.ts    — направление А (новое)
  holoTheme.ts        — направление Б (новое)
  index.ts             — реестр Record<MapStyleId, MapTheme>
```

Почему так, а не веткой `if (style === ...)` прямо внутри `drawTerritoryGlow`/`drawSystemGlyph`:
1. Не раздувает и без того большие функции тремя параллельными ветками.
2. **Параллельно-безопасно для двух агентов** — Composer 2.5 и Grok 4.5 могут работать одновременно, каждый в своём новом файле (`imperialTheme.ts` / `holoTheme.ts`), не трогая один и тот же код. Единственная точка пересечения — `index.ts` реестр (две строки: импорт + запись в объект), это тривиально мёржится или делается последним отдельным шагом.
3. `classicStyle.ts` — текущее поведение 1:1, без изменений картинки. Это откат/дефолт на всё время разработки.

`mapStyle` — **чисто отрисовочный** параметр (влияет только на то, какие цвета/формы рисуются), не на WebGL-контекст (`antialias`/`resolution`/`powerPreference`, которые зафиксированы при создании `Application` и требуют пересоздания canvas, как это устроено для `perfMode` через `key={viewer-map-${perfMode}}` в `ViewerPage.tsx`). Значит переключение стиля **не требует remount** — работает через тот же живой `redrawAll()`, что и `graphics.territoryGlow` сегодня. Подробности и код — в `01-SHARED-FOUNDATION-TASKS.md`.

## 5. Не трогать (осознанно вне скоупа)

- **Артефакты иконок** (`/icons/game/*.svg`, ~50 файлов game-icons.net + генерируемые ресурсные иконки) — не перерисовываем. Тема меняет только плашку/рамку под иконкой (`MapIconOverlay.plates` в `mapIconSprites.ts`), не сам силуэт. Перерисовка полного набора иконок — отдельный, кратно более дорогой проект.
- **Семантические (не фракционные) цвета** — `ORDER_ARROW_COLORS` (`src/state/defaults.ts:37-48`: атака=красный, движение=синий, оборона=зелёный, блокада=янтарный...), `ACTIVITY_COLOR`/`POI_TINT`/`ACTIVITY_TINT`. Это язык статуса/угрозы, не бренда — он обязан быть одинаковым во всех трёх темах, иначе игрок теряет способность читать угрозу по цвету при смене темы. Единственная разрешённая правка здесь — техническая (см. `04-INTEGRATION-QA-TASKS.md`, пункт про дублирование `ACTIVITY_COLOR`/`ACTIVITY_TINT`), не косметическая.
- **Перф-тиры / WebGL-контекст** (`resolvePerfTier`, `Application.init()` параметры) — не меняются.
- **`classic` остаётся дефолтом** до отдельного решения — это не миграция «заменить старое», это добавление опции.
