# Силы (Forces) — задачи

Файлы: `src/viewer/forces/ForcesDeck.tsx`, `UnitCard.tsx`, `useDeckGestures.ts`, `DropZones.tsx`, `constants.ts`.

## ⚠️ Контекст — читай перед тем, как трогать

Силы — единственный крупный раздел, который **не использует** общую `CardBoard`/`DragCard`/`DropZone` систему из `01_PRINCIPLES_AND_GUARDRAILS.md`. У него собственная, независимая система жестов: сырые pointer-события + `document.elementFromPoint` + data-атрибуты (`data-drop-zone`/`data-unit-card-index`), реализованная в `useDeckGestures.ts`. По аудиту на момент редизайна это уже примерно 50/50 — реальный жестовый флоу (драг, долгое нажатие) для главного действия «назначить/переставить юнита», обычные кнопки для второстепенного («прикрепить из резерва» и т.п.) — то есть **раздел уже работает хорошо**, это не сломанное состояние, а сознательно другая архитектура.

**Не переписывай эту систему только ради единообразия с `CardBoard`.** Объединение — отдельная, рискованная задача (два конкурирующих механизма жестов на карточках юнитов, которые уже тонко настроены — см. комментарии в коде типа «Never fire long-press once a drag has started» и «Stay in the deck — never navigate mid-gesture (was freezing the tab)» — это следы уже пофикшенных багов, значит система хрупкая и уже один раз ловила регрессии).

## Задачи (в порядке возрастания риска)

- [ ] **Низкий риск:** аудит без изменений — убедись, что текущее состояние файла соответствует описанному выше (50/50 драг/кнопки), и что ничего не сломано параллельными правками других агентов.
- [ ] **Низкий риск:** если где-то в Силах остались явно избыточные ring/long-press поверх уже кликабельных элементов — почисти по той же логике, что и Склад Экономики (кнопка вместо дублирующего кольца), но НЕ трогай сам механизм драга юнитов.
- [ ] **Средний риск, требует отдельного согласования, не делай без явного запроса:** унификация `useDeckGestures` с `CardBoard`, чтобы карточка юнита из Сил могла быть перетащена, например, на Двор (назначить командующего) или на карту (напрямую перебросить флот) через общую доску. Это даст красивую кросс-разделную возможность, но требует переписать рабочий, протестированный код — сначала напиши отдельный план с конкретными рисками регрессии, не бросайся сразу переписывать.
