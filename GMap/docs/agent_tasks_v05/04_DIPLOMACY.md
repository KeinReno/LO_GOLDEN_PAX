# Дипломатия — задачи

Файлы: `src/viewer/ViewerDiploPanel.tsx`, `src/viewer/DealDesk.tsx`, `src/viewer/DiploDealTray.tsx`, `src/viewer/DiploSwipeOffer.tsx`, `src/viewer/DiploCompareStrip.tsx`, `src/viewer/ContactMarketStrip.tsx`.

## Контекст

Это один из самых зрелых разделов по части жестов уже сегодня: `DiploDealTray.tsx` собирает сделку через `DragCard`/`DropZone` (карточки ресурсов/договоров в зоны «Отдаю»/«Прошу»), `DiploSwipeOffer.tsx` реализует свайп принять/отклонить для входящих предложений с кнопочным фолбэком для доступности. Это референсный паттерн для свайпа — если другой раздел (Квесты, Двор) захочет такой же свайп-приём, смотри сюда, а не изобретай заново.

`accepts={["*"]}` в `DiploDealTray.tsx` уже заменён на точный список `DIPLO_TRAY_CARD_IDS` (валюты + договоры) — если увидишь wildcard снова, это регрессия, смотри `01_PRINCIPLES_AND_GUARDRAILS.md`.

## Задачи

- [ ] Проверь, что `DIPLO_TRAY_CARD_IDS` (или её нынешний эквивалент) не остался стилистически «зашитым» списком, если появились новые типы карточек в лотке — список должен пересчитываться от актуального набора валют/договоров, не быть забытой константой.
- [ ] Живой предпросмотр во время драга (урок Reigns, см. `01_PRINCIPLES_AND_GUARDRAILS.md`): когда игрок тащит карточку ресурса в «Отдаю»/«Прошу», подумай, можно ли показать примерную оценку выгодности сделки уже во время движения (до отпускания), а не только после сборки предложения. Необязательно, но хорошо ложится в общий язык, раз `TaxDragStrip`/`RpsChain` в Экономике уже так делают.
- [ ] Кросс-разделная карточка: раз `CardBoard` теперь общий на весь вьюер (см. `01_PRINCIPLES_AND_GUARDRAILS.md`), проверь, имеет ли смысл разрешить перетащить карточку ресурса **прямо со Склада Экономики** в открытую Дипломатию, минуя ручной ввод — вероятно, требует, чтобы обе панели были видны одновременно (десктопный воркбенч), либо доковой иконки как точки приземления (см. подход `map-canvas` DropZone в `ViewerPage.tsx` как пример моста между разделами).
- [ ] Проверь `ContactMarketStrip.tsx` — это, по замыслу, тот же UI-язык, что и адресная торговля с сверхдержавой в Бирже (вкладка «Державы»/`market-super-card`) — если Биржа развивает этот паттерн отдельно, синхронизируй, чтобы не разошлись два похожих, но разных виджета для одной и той же задачи «сделка с конкретным контактом».
