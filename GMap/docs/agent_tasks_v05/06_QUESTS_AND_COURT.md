# Квесты и Двор — задачи

Файлы: Квесты — `src/viewer/quests/*`, `src/viewer/QuestDossier.tsx`, `ViewerQuestPanel.tsx`. Двор — `src/viewer/CourtPanel.tsx`, `src/viewer/court/*` (`CourtFieldView.tsx`, `CourtHousesView.tsx`, `CourtNationsView.tsx`, `NpcCard.tsx`).

## Контекст

Оба раздела уже используют `DragCard`/`DropZone` на общей доске, и в обоих сегодня же закрыта дыра `accepts={["*"]}`:
- Квесты: `QuestDossier.tsx` — точный список `choiceCardIds` (id текущих вариантов выбора квеста).
- Двор: `CourtPanel.tsx` (2 места) + все три под-вида (`CourtFieldView.tsx` ×3, `CourtHousesView.tsx`, `CourtNationsView.tsx`) — точный список `npcCardIds` (все НПЦ державы, включая посаженных и в пуле).

Если увидишь `accepts={["*"]}` в любом из этих файлов снова — это регрессия, чини по образцу: собери `useMemo`-список id из уже существующего массива НПЦ/вариантов, не выдумывай новый источник данных.

## Задачи — Квесты

- [ ] Рассмотри перенос свайп-паттерна (`DiploSwipeOffer.tsx`, см. `04_DIPLOMACY.md`) на входящие квесты/петиции — это концептуально тот же «бинарный выбор без места назначения», что и дипломатическое предложение. Не обязательно, но давно напрашивается и явно относится к тому же семейству жестов.
- [ ] Проверь `QuestChatPanel`/`AttentionInbox`/`QuestStage` на предмет действий-кнопок, которые на самом деле являются «драг с назначением» (например, назначение НПЦ на квест, если такая механика есть или планируется) — если да, используй `DragCard` с уже существующим `choiceCardIds`-подобным точным списком принимающих id.

## Задачи — Двор

- [ ] Прогони проверку на дубль-жест (баг из `01_PRINCIPLES_AND_GUARDRAILS.md`): есть ли где-то в `CourtPanel.tsx`/под-видах `useLongPress` или `ActionRing`, навешенные на тот же элемент, что уже является `DragCard` (например, карточка НПЦ в пуле, `NpcCard.tsx`)? Если да — почини по той же схеме, что Склад: явные кнопки вместо кольца, долгое нажатие — только на отдельной небольшой зоне, если вообще нужно.
- [ ] Проверь, что `npcCardIds` в `CourtHousesView.tsx` (там это проп `acceptCardIds`, проброшенный из родителя в дочерний `HouseCard`) пересчитывается корректно при изменении состава НПЦ — это единственное место, где список принимающих id передаётся через проп в отдельный компонент, а не вычисляется на месте, легко забыть обновить при рефакторинге.
