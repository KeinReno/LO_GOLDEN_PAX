# RP и Справочник (Codex) — задачи

Файлы: RP — `src/viewer/RpStage.tsx`, `src/editors/FloatingRpWindow.tsx`, `src/editors/RpChat.tsx`. Справочник — `src/viewer/codex/CodexPanel.tsx`, `CodexEntry.tsx`, `codexData.ts`, `codexResolve.ts`.

## Контекст

Эти два раздела **не разбирались подробно** в рамках основного редизайна — в отличие от Карты/Экономики/Биржи/Дипломатии/Двора/Квестов, здесь нет готового вердикта «что чинить». Не переписывай наугад — сначала прочитай `01_PRINCIPLES_AND_GUARDRAILS.md` и посмотри, попадает ли текущая реализация под уже описанные принципы или нет.

## Задачи — RP

- [ ] Аудит: RP — это, по сути, чат/сцена с ГМ. Скорее всего, здесь вообще не должно быть драг-жестов (нет ни цели переноса, ни объекта) — подтверди это, а не добавляй жесты ради единообразия.
- [ ] Проверь непрочитанные сообщения (`rpUnread`) и их связь с `OrderTray`/доком — не должно быть второго, отдельного счётчика непрочитанного, дублирующего бейдж на доковой иконке RP.
- [ ] Если в RP есть какие-то carousel/выбор реплик — проверь, не подходит ли туда свайп-паттерн из `DiploSwipeOffer.tsx` (см. `04_DIPLOMACY.md`) для быстрых бинарных реакций.

## Задачи — Справочник

- [ ] Справочник — чистый reference/поиск, высокочастотный просмотр списка. По принципам из `01_PRINCIPLES_AND_GUARDRAILS.md` это НЕ кандидат на карточный драг (частый просмотр списка — тап/скролл, не жест с целью переноса).
- [ ] Рассмотри такую механику: долгое нажатие на любой игровой объект в ДРУГИХ разделах (юнит, технология, здание, держава) открывает соответствующую статью Справочника контекстно (см. упоминание такой идеи в общем обсуждении — «долгое нажатие = узнать больше» не конфликтует с «долгое нажатие = подтвердить» для объектов, у которых нет разрушительного действия). Это не обязательная, а предлагаемая к рассмотрению фича — согласуй масштаб, прежде чем реализовывать во всех разделах сразу.
- [ ] Проверь, не задваивается ли фильтрация/поиск в Справочнике с чем-то похожим в других разделах (например, список технологий и там, и в Науке) — если да, подумай про переиспользование одного источника данных вместо двух параллельных копий (та же дедупликация, что уже сделана в Штабе относительно Экономики).
