# Сквозные задачи (не привязаны к одному разделу)

Все пункты ниже были осознанно вынесены за скобки при работе над фундаментом и Картой — не потому что не важны, а потому что каждый требует отдельного внимания. Бери по одному, не смешивай.

## Из плана Карты, осознанно отложено

- [ ] **Настоящий приказ каравана.** Сегодня перетаскивание ресурса на систему (со Склада или прямо на карту) вызывает `onCaravanHint` — это ПОДСКАЗКА («перевозку оформите приказом на карте»), а не реальный приказ. `ViewerPage.tsx`, функция `caravanHint`. Если есть возможность добавить настоящий intent на бэкенде — замени заглушку.
- [ ] **Живая точечная подсветка системы во время драга по канвасу.** Сейчас `DropZone` для канваса карты (`zoneId="map-canvas"` в `ViewerPage.tsx`) — один невидимый прямоугольник на весь канвас; во время перетаскивания карточки ресурса нет подсветки конкретной системы под курсором, только по факту сброса. Чтобы сделать live-highlight, `DragCard` должен получить новый continuous-колбэк «двигаюсь над зоной X» (сегодня `DragCard` сообщает о попадании в зону только на `first`/`last` жеста, не на каждый `move`) — это небольшое, но настоящее расширение API `DragCard.tsx`.
- [ ] **Мобильная раскладка `OrderTray`.** Сейчас общий лоток ОД/ОД сил (`src/viewer/OrderTray.tsx`) показывает оба счётчика рядом всегда, десктопная раскладка не адаптирована под мобильный узкий экран отдельно (только базовый `@media (max-width: 720px)` уменьшающий отступы). Мобайл в целом сознательно отложен как отдельная большая задача — не пытайся её закрыть попутно с чем-то другим.
- [ ] **Изометрический стиль будущих визуальных прототипов.** Если делаешь новый интерактивный прототип/мокап интерфейса (например, для демонстрации нового раздела) — реальная карта рендерится изометрически (`src/renderers/iso.ts`, `toIso`/`fromIso`), не плоским топ-дауном. Учитывай это в визуальных мокапах, если они претендуют на «как это будет выглядеть по-настоящему».

## Из аудита CardBoard/DragCard

- [ ] **Консолидация редакторских (ГМ) `CardBoard`.** `src/editors/DiplomacyPanel.tsx` и `src/editors/gm/GmLiveStage.tsx` держат собственные локальные `<CardBoard>` — это отдельные от вьюера страницы (маршрут `/` вместо `/view`), сознательно не тронуты при объединении доски игрока. Если понадобится кросс-переносимость карточек внутри самого ГМ-редактора — это отдельная, самостоятельная задача, не смешивай с работой над вьюером игрока.
- [ ] **`DragCard` continuous-колбэк для наведения на зону** (см. пункт выше про live-highlight) — если реализуешь, заодно проверь, не пригодится ли он ещё где-то (например, для превью «куда попадёт» при драге НПЦ в Дворе на большом расстоянии от исходной зоны).

## Мелкие визуальные хвосты

- [ ] Метка стека («×N» у нескольких флотов в одной точке) и бейдж стойки боя не участвуют в новой анимации перемещения (`src/renderers/MapCanvas.tsx`, `unitTransitRef`) — они рисуются через `Graphics`, перерисовываются с нуля на каждый dirty-редрав в финальной позиции, поэтому во время ~650мс перелёта юнита выглядят так, будто уже «доехали», пока сам спрайт ещё летит. Мелкий, не критичный визуальный нюанс — почини, если будет время, не приоритет.
- [ ] `hq-outliner` (Штаб, `PlayerOrdersPanel`) и `market-super-card` (Биржа, вкладка «Державы») — классы без собственного CSS-правила (используются вместе с `hq-card`, который стилизован, так что не критично, но не единообразно с остальными карточками).
